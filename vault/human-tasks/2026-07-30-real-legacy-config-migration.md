If you still have one — check `~/.kubecom.yaml`, and any dotfiles backup or old laptop:

1. **Keep a copy first**: `cp ~/.kubecom.yaml ~/.kubecom.yaml.bak`. Migration does not

2. Make sure no new-format config exists yet, or migration is a deliberate no-op:
   `ls ~/.config/kubecom/config.yaml` (macOS: `~/Library/Application Support/kubecom/`).
   If one exists and you want to see the migration run, move it aside.
3. Run `kubecom`. On the first start it should migrate once and show a startup toast.
4. Paste back into `vault/feedback/`:

     no such field, but paste-what-you-see beats paste-what-you-remember),
   - the **toast text** (it is transient; `~/.cache/kubecom/kubecom.log` has the
     `migrated legacy config` line and the note count if you miss it),
   - the **written `config.yaml`**.

## What we want to learn from it

- **Did anything fail to parse?** A parse failure degrades silently to "no migration" by
  design (D92) — you would see *no* toast and no `config.yaml`. That outcome is the single
  most useful thing this task can find, and it is invisible from inside the sandbox.
- **Is the menu note's list actually useful?** It names each legacy entry by title, and a
  real menu is longer than the fixture's four. If the toast is a wall of text at your
  terminal width, that is a finding — the note, not the terminal, is wrong.
- **Did your theme come across?** If you ever pressed the 2020 theme-cycle key, `currentTheme`
  holds one of `base16`/`monokai`/`paraiso`/`solarized`/`twilight`. `monokai` and `solarized`
  carry over (the latter as `solarized-dark`); the other three land on v1's default and say so
  (D179). If yours was one of those three and the note reads as a loss rather than a choice,
  say so — that is a wording call, and possibly a "port that palette" request.
- **Did you hand-edit `themes:`?** The 2020 app never wrote that key itself, so a palette
  tree there means you authored it. v1 has no field for a custom palette; if you actually
  want one, that is a feature request and belongs in `vault/feedback/` (D179 pt 1 explicitly
  refuses to invent the field as part of a migration).
