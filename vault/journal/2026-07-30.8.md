## The leg the board asked for, and why it was the wrong question

The board framed M5-01b as a maintainer decision with two branches: re-add a read-only YAML
view, or amend the DoD bullet. Both were framed as defensible, and they are — "one surface
for read+write is simpler" versus "glancing at YAML is a read gesture that should not leave
the TUI" is a genuine taste call.

Except it was not open. D135's opening line names its cause: feedback
`2026-07-24-unify-yaml-view-and-edit`. That file is gone — D69 deletes an addressed item in
the leg that addresses it — so the only surviving trace in the working tree is D135 itself,
which reads exactly like an agent decision, complete with an agent's rationale. `git show`
brings the maintainer's own words back:

> Having a separate read-only **YAML viewer** (`y`) and a separate **edit** (`e`) action is
> redundant. Collapse them into **one action that opens the object's YAML in a proper
> editor** … "Proper editor": prefer suspending to the user's real `$EDITOR` (the M3-15b
> flow) so they get their own editing environment — that IS the "proper editor" for YAML.

That is not a decision the agent may reverse, and it is not one the maintainer needs to be
asked about twice. It also inverts the two branches: re-adding a read-only YAML viewer —
the branch the board listed first, and the cheap one, since the `viewer` component and the
`YAMLGetter` seam both survived — would have been an autonomous leg undoing an explicit human
request. The only correct move was the amendment.

## Amending a DoD bullet without doing what D174 pt 3 forbids

D174 pt 3 is a good rule: "Rewriting the bullet to match the code would erase the only
remaining record that a v1 promise changed shape, and the DoD is the maintainer's contract,
not the agent's scratch pad." The failure it prevents is an agent quietly trimming promises
down to whatever it managed to build.

The distinction that makes this leg legal, and which D178 pt 1 now states, is **whose
decision it was**. Amending a bullet because the code went a different way is the forbidden
move. Amending it because the human said so is transcription. And the erasure D174 worried
about is avoided directly rather than by argument: the annotation carries the original text
verbatim ("It read … until then"), the maintainer's quote, the `git show` that produces the
full file, and the pointer to D135/D136/M3-15c. The record is *stronger* after the edit than
before, because before it took reading D174 to learn that a promise had changed shape and
`git log` to learn who changed it.

The bullet stays **unticked**, which is the other half of being honest here. It would have
been easy to declare the box met — logs and describe are in-TUI, YAML has a surface, no
pager is involved — but reading YAML now rides the live `$EDITOR` suspend, and that suspend
has never been driven by a human. It is precisely why the Exec/Edit box below is unticked.
So the box moves from "waiting on a question" to "waiting on the same evidence as its
neighbour", which is real progress: after this leg **no DoD box waits on a decision**. Four
wait on a dogfood or a bug, three on work not yet done. M5-10's pre-flight, which wanted the
DoD closed, now has a list where every remaining item names a thing that happens, not a thing
someone must choose.

## The bug that fell out of it

Because the divergence was filed rather than chased, nobody had checked whether anything
*else* still promised the retired viewer. `README.md` did, in the sentence right after the
logs view:

> `Esc` with no filter open, or `q`, closes the view. YAML, describe and secret content
> still open in the shared centered viewer — only logs stream, so only logs get their own
> screen.

False since M3-15c, three milestones back, in the file a new user reads first — the same
class of defect as M5-04's migration note, found the same way (a claim nobody re-read after
the behaviour under it moved). Worse, the README never documented `e` **at all**: grepping
it for `EDITOR` returned one hit, in an unrelated sentence about config files. So a reader
was told to look for a YAML viewer that does not exist and never told about the key that
does.

Fixed both in one paragraph, and every claim in it was read out of the code rather than
inferred from D135's summary: the `KUBE_EDITOR`→`EDITOR`→`vi` chain and the whitespace argv
split (so `EDITOR="code -w"` is honest), that closing unchanged sends nothing, and that a
save is validated server-side with a resourceVersion conflict check — which is worth stating
in a README because "will this clobber my colleague's change?" is a fair question to have
about a TUI that edits live objects. The paragraph also says the unification out loud
("deliberately one gesture rather than two keys"), since a user who knows k9s or the 2020
build will go looking for `y`.

## Two small vault repairs, and the general lesson

`vault/feedback/README.md` mandates deletion but never said where the words go, which is how
this leg's whole confusion was possible. It now carries the two commands that bring a deleted
item back, framed as the reason to run them: a decision written from your feedback reads like
the agent's own idea once the file is gone.

M3's Scope still listed "**YAML viewer**: get object as YAML → viewport" — annotated as
superseded rather than deleted, matching how its own exit criterion already handled the
change. The board's M3-03 and M3-15c Done entries were left alone: those describe what legs
did on the day they did it, and rewriting completed history is a different and worse habit
than fixing a live promise.

The transferable part is D178 pt 2. This vault deliberately deletes two kinds of file —
addressed feedback (D69) and resolved human tasks (D79) — and both are exactly the places
where a *human's* words live. The consequence is subtle: the working tree systematically
under-represents how much of this rewrite the maintainer decided, and an agent reading only
the live tree will keep mistaking answered questions for open ones. Git has all of it. The
check costs one command, and this leg is the evidence that skipping it costs a leg.
