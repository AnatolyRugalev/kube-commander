# 2026-07-28 — SEARCH-04c-1: label-selector matching for cluster search

- Agent: claude-opus-5
- Milestone: M3 (the SEARCH line is a feedback-pulled M4 capability, D131)
- Did: Split SEARCH-04c on pickup as its own notes predicted, and took the first half.
  The search query line now accepts a `-l <selector>` term: `api -l app=web` matches the
  name substring *and* the label selector, `-l app=web` matches on labels alone.
  `kube.Search`'s query parameter became a `SearchQuery{Name, LabelSelector}` and the
  selector rides `metav1.ListOptions` into every kind's List. → D151.
- **The selector is the first search term that makes a search cheaper.** Every SEARCH leg
  so far has spent something — a wider kind set, a wider namespace, a longer sweep — and
  the whole design has been about bounding that cost (D149 pt 4's semaphore, the debounce,
  the cap). A label selector is the opposite: the apiserver evaluates it and returns fewer
  rows, so it narrows the wire *and* the result. That is why it is not gated behind
  anything, does not reset per visit the way a widen does (it is part of the query, not
  the scope), and pairs naturally with `ctrl+a`/`ctrl+w` — it is the only way to widen the
  scope and narrow the answer in the same breath.
- **Field selectors were considered together with labels and deliberately dropped**, and
  the reason is the interesting half of the leg. They look equally free — same
  `ListOptions`, same server-side evaluation — but supported fields are *per kind*
  (`spec.nodeName` is a Pod thing, `status.phase` nearly so), and a kind that does not
  support the field rejects the List. Under this search's per-kind fault isolation
  (D131 pt 3) a rejected List is a **silent** failed kind. So one `f:spec.nodeName=n1`
  would make most of a cross-kind fan-out vanish without a word, while the progress line
  still counted cheerfully to N/N. The general rule that fell out (D151 pt 2): a
  cross-kind surface may only carry terms *every* kind can answer. Labels qualify — every
  object has `metadata.labels` and every List accepts a label selector.
- **Shape detection was available and is wrong.** The tempting parse is "if it parses as
  a label selector, treat it as one" — no syntax to learn. But `labels.Parse("nginx")`
  succeeds: a bare identifier is the existence selector *has label `nginx`*. Sniffing
  would therefore reinterpret the single most common query in the app as a label lookup
  and return nothing. Hence an explicit whitespace-delimited `-l` token (kubectl's own
  flag, so there is nothing new to learn anyway), with the token test written so a `-l`
  inside a word never splits a name: `my-lb` is a name, `api -lapp=web` is a (useless but
  honest) name, only a free-standing `-l` is the operator. The remainder after it is taken
  *whole* rather than tokenised, which is what lets `-l tier in (a, b)` work — and is
  defensible because an object name can never contain a space, so a multi-term name half
  would buy nothing and cost a grammar.
- **Parsing happens per keystroke, not at launch, and that is a UX constraint not an
  optimisation.** A selector is invalid for most of the time it is being typed (`-l app=`
  is the moment before `-l app=web`). If parsing waited for the debounced launch, the
  error would arrive a beat after the reader had already moved on. It is parsed in
  `restartSearch` and, when it fails, surfaced through the view's new `SetQueryError` —
  in the error style, in place of the empty hint, outranking `no matches`. That priority
  is the point: an unparseable selector that *was* sent would fail every kind's List and,
  by exactly the mechanism above, render as a healthy empty cluster. A typo must never be
  indistinguishable from an answer.
- The one discoverability move: the blank-query hint now reads `type to search this
  cluster · -l app=web to match labels`. Syntax is the one thing in this view a reader
  cannot find by pressing keys (the hint bar covers the keys, `?` covers the rest), and
  that line is already on screen at exactly the moment they are wondering what to type.
  No new keybinding, so `docs/keybindings.md` is unchanged.
- Small thing worth remembering: `labels.Parse("")` is `Everything()` whose `String()` is
  `""`, so an empty selector round-trips to "no selector" with no special case, and
  `Selector.String()` normalises (`tier in (a, b)` → `tier in (a,b)`) — which is why the
  parsed form is what gets stored and compared. Written up in `vault/knowledge/stack.md`
  along with the bare-identifier trap.
- Decisions: D151 — a search term goes to the server whenever the server can evaluate it;
  a cross-kind surface may only carry terms every kind can answer (why field selectors are
  out); an unusable query is reported where it was typed and never sent; a grammar in a
  text field discriminates by an explicit token, never by shape.
