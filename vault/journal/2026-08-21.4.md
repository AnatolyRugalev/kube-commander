- Did: Landed both halves of the board item, closing two feedback files. (1) A launch
  or a context switch with nothing recorded now opens the **Pods** table instead of the
  welcome pane: `WithLastResource` arms the restore whatever it is handed and
  `restoreLastResource` falls back to `defaultLandingResource`, so the default rides the
  same discovery-gated, silently-degrading path a remembered kind does. (2) The
  resources pane **holds back discovered custom resources**: a `Custom Resources` row
  with neither an authored `menus/<context>.yaml` entry (`Item.Authored`) nor a pin
  (`Item.Pinned`) behind it is dropped from the displayed list in `applyFilter`, while
  `Items()` keeps every kind so the picker, `:pin`, cluster search, the unhealthy sweep,
  relations and pane memory are unaffected. Reachability: an explicit `/` query in the
  pane reveals them, the open kind is always listed (`SetActive` re-derives), and a
  trailing `+N custom · / to find` row reports the count. `AddPinned` now marks a row
  discovery already listed rather than skipping it (otherwise pinning a CRD was a
  no-op under the new default), and `Unpin` re-derives so the row leaves the pane
  while the kind stays in the inventory.
- Also: the displayed list is no longer index-addressable from `Items()`, so pane
  memory selects by GVR through the new `menu.SelectResource`, and it does so *after*
  `selectResource` — the row only exists once the kind is the active one.
