## The second door was the leg, not the key

`ctrl+n` itself is one name added to a `handleAction` arm — the same five-character edit
`R` was. What made PAL-05c-1 its own slice is that the namespace picker had **two**
openers, and only one of them is a key. Drilling into the menu's namespace-seam row emits
`menu.NamespaceRequestedMsg`, which the root has opened the picker on since M2-08c/D82.
Convert the key and stop there and the tree is still green, the lint gate is still happy
(the picker still has a caller), and the retired surface is alive behind a menu row — the
exact dormant-second-surface state D207 pt 3 exists to prevent, reached without
triggering the linter that enforces it. That is D208 pt 1, and it is worth stating
because the *mechanism* D207 pt 3 leans on (`unused` in the lint gate) does not fire
here: an opener with one caller left is not dead code.

The seam row keeps its message and its meaning. What changed is one line of routing.

## What retiring the most-referenced picker actually deleted

`nsPicker` was 52 references across 9 files, and the interesting part is that most of
them were not the picker — they were the *default*. Because `nsPicker` was the first
picker (M2-08c), it was the one the root fell through to: `picker.SelectedMsg` and
`picker.CancelledMsg` both ended in `default:` meaning "the namespace picker", and half a
dozen tests delivered a bare `picker.SelectedMsg{Value: "kube-system"}` on the strength of
that. So this leg did not just remove a surface; it removed the *unnamed* one, and every
picker is now routed by a Kind it stamps.

That is D208 pt 2, and it flips the failure mode for whoever adds the next picker: an
unstamped Kind used to be misrouted (a container selection applying a namespace), and is
now dropped. Dropped is the better failure — silent inertness is debuggable and
harmless, misapplication is neither — but it is a *different* failure, so it is written
down rather than left to be rediscovered. The tests that leaned on the default were
re-pointed through `openNamespaceStage`, which presses the real key and delivers the real
list, so they now assert the same behaviour one layer closer to what a reader does.

## The `dest` collapsed; the wait did not

D199 gave `namespacesLoadedMsg` a `dest` because two surfaces issued the same load and a
result carried no other way to say which one asked. One surface left, so the field went —
but the guard it sat next to is not the same guard. `dest` answered *which surface*;
`awaitingPaletteArg` answers *is that stage still up*, and the second question survives
the first perfectly well: a list that lands after the reader backspaced the line to the
verbs would otherwise seed the verb list with namespaces. Nothing pinned that before this
leg (the old `waiting` check was entangled with the routing), so it now has its own test,
and the test was confirmed by mutation. D208 pt 3 says it once for PAL-05c-2, which is
about to make the identical collapse to `contextsLoadedMsg`.

## One test fake got closer to a real cluster

`newClusterFake` built a `Cluster` with a watcher and a discoverer and no namespace
lister, which was fine while `ctrl+n` read `m.nsLister` on the Model directly through its
own opener. Once the key routes through `enterPaletteArg`'s inertness check, a
switched-to cluster with no lister makes the key inert — and
`TestSwitchRebindsPerContextState`, which picks a namespace *after* a switch to prove the
persister was rebound, could no longer reach the pick. The fix is the fake carrying a
lister, because a real switched-to cluster carries one: the test now drives the rebind
through the surface a reader would use instead of through a synthetic message. Worth
noting as the general shape — a conversion that routes a gesture through a shared
precondition will find the fakes that were never asked to satisfy it.
