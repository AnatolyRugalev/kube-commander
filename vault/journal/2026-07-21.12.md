# 2026-07-21 — FB-mouse-support: additive mouse (click to open/select, wheel to scroll)

- Agent: claude (Opus 4.8), autonomous leg
- Milestone: M2
- Did: Addressed the last dogfood feedback in the inbox
  (`2026-07-21-08-mouse-support`, normal). Enabled Bubble Tea mouse reporting and
  wired the three requested gestures, keeping the keyboard/vim path primary (goals
  principle 6). Mouse mode is a per-View property in bubbletea v2 (like AltScreen,
  D70), so `View` sets `v.MouseMode = tea.MouseModeCellMotion` on both return paths;
  the root `Update` handles `tea.MouseClickMsg` and `tea.MouseWheelMsg`. A left click
  in the **menu** pane selects the clicked resource row and drills into it (opens its
  table / opens the namespace picker for the seam row); a left click in the **table**
  pane selects the clicked data row and moves focus there; the **wheel** steps the
  selection of whichever pane the pointer is over (X < `menuPaneWidth` = menu) without
  changing focus. Every gesture is turned into the same `keymap.Action` or public
  `Select*` call the keyboard drives — no view matches a raw mouse event (D11 in
  spirit). The coordinate→row mapping is pure component code: `menu.RowItemAt` and
  `table.RowAt` convert a content-area row (composing the scroll offset) to an item/row
  index, rejecting section headers, the table column-header line, borders and blanks;
  the root converts an absolute mouse (X,Y) to a body-relative content row (Y-1, above
  the status bar) and picks the pane by X. Mouse is inert while an overlay is up (help
  / namespace picker / live filter) so a stray click can't reach the panes beneath a
  modal.
- Decisions: **D86** — mouse is additive and routed through keymap Actions / public
