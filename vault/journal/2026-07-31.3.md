## Why b-1 and b-2 are different legs

M1-INT-b read as one item with two assertions. It is not: they need different machinery.

A **transport drop** is produced *between* the client and the server, so the test needs a
pipe it can cut — and nothing about the control plane changes. An **expiry** can only be
produced *by* the server, and the probe that settled the split showed a stock envtest
plane will not produce one at all:

| watch from | after | result |
| --- | --- | --- |
| `resourceVersion=1` | nothing | no events, no error — waits |
| `resourceVersion=1` | 150 pod creates | **replays all 150 events** |
| an RV held from before 150 creates | those creates | replays the 150 it missed |

So the RV window here is etcd's revision history, not the watch cache's size (150 writes
is past the default 100-event cache), and nothing compacts etcd on a plane that lives for
six seconds — `--etcd-compaction-interval` defaults to 5m. b-2 therefore has to configure
the apiserver before `env.Start()`, which `startControlPlane` cannot currently express.
Landing that machinery inside b-1 would have doubled the leg for an unrelated assertion.

## What the test actually breaks

`startKillableProxy` is a raw TCP proxy on loopback that forwards to `cfg.Host` and can
close every connection it is carrying. Raw TCP, not an HTTP proxy, so TLS still terminates
at the apiserver: the client's behavior is unchanged except that the wire can be cut. The
watcher gets a `rest.CopyConfig` pointed at the proxy with `ServerName` carried over from
the real host, so the serving certificate still verifies — the proxy is a pipe, not a MITM.

Writes go through the **direct** client. If the writer shared the proxied connection the
drop would break the write too, and the test would be measuring its own plumbing.

## The two ways it was watched fail

A test that has not been watched fail is not evidence, and this one had two distinct ways
to pass vacuously — one where nothing breaks, one where the wrong thing is asserted.

1. **Comment out `proxy.dropAll()`.** The pod created "during the outage" arrives on the
   still-open stream and every assertion about it passes. The dial counter is what catches
   it: `proxy dials = 1, was 1 before the drop: the delta arrived without a reconnect, so
   this test proved nothing`. This is why the count is in the test at all — the resume
   claim is *about* a second connection, so the second connection has to be asserted.
2. **Break the resume path** (`if true || errors.As(werr, &exp)` in `watchLoop`, i.e.
   re-List after every stream error): `a transport drop re-listed: got RESET with
   [before-drop during-outage], want a resumed stream`. Note that the rows are *correct* —
   a re-List loses no data, which is exactly why this regression would be invisible in
   any assertion about content. What it costs is a full-table replace in the consumer on
   every network blip (D34's RESET contract: replace your whole row set), i.e. the cursor
   and the render. The cheapness of the reconnect is the property under test.

A transient `WatchError` during reconnect is tolerated and logged rather than failed —
reconnecting *may* report a failure, and the RESET assertion still catches it if that
failure turns into a re-List. In practice none was observed across runs.

## Cost

The plane starts in ~4 s and the whole test takes ~6 s, of which 2 s is
`watchRetryBackoff` — the loop's own pacing, not slack in the test. The full gated suite
is now four tests / four control planes in 19 s, which is still comfortably a per-leg
command rather than something to amortize with a shared plane (`startControlPlane`'s
per-test isolation is load-bearing for the tests that wreck cluster-global state).
