- **Auditing the scope was most of the value, and it found four concrete gaps.** Three of
  them are defects rather than unbuilt features, which is exactly what a plan leg is for —
  each would otherwise have been discovered by a release that had already shipped:
  - **`Commit` and `Date` are never set.** `internal/version` declares all three fields and
    `Info()` prints all three, but `.goreleaser.yml`'s ldflags sets only `Version`. Every
    released binary would report `commit none, built unknown` — the first line a bug report
    quotes — and after a tag ships it is unfixable in place. Now **M5-02**, deliberately
    ordered before anything that publishes.
  - **There is no release workflow at all.** Exit criterion 2 says `goreleaser release`
    runs from a tag via CI; `.github/workflows/` contains only `ci.yml`. The goreleaser
    skeleton (M0-06/D27) has never been executed by anything. Now **M5-03**, which also
    adds the `--snapshot` dry-run job so the config stops being untested.
  - **A shipped migration note has been lying since M4-11.** `migrationNotes` tells a 2020
    user "legacy theme configuration was dropped: kubecom v1 uses a single fixed theme and
    has no runtime theming". True under D6 when M2-12a wrote it; false since the themes
    line landed. A legacy `currentTheme: monokai` is reported as dropped by a binary that
    ships a `monokai` palette, a `theme:` field (D170) and a picker (D172). Now **M5-04**.
  - **The Definition of Done is entirely unticked** — 12 boxes, and M1–M4 demonstrably
    delivered most of them. This is the M4-PLAN lesson repeating: #85 had been met in M2
    for a week before anyone looked. Now **M5-01**, and it is deliberately the *first*
    slice, because the one thing worse than a missing feature at release time is not
    knowing whether it is missing.
- **Why M5 needed a decision of its own and not just a task list.** Every milestone so far
  ran on "green or revert". M5 has no revert: `proxy.golang.org` caches a module version
  permanently, so a broken `v1.0.0` cannot be replaced, only superseded. That single fact
  reorders the milestone — everything determining *what the artifact contains* has to land
  before anything that publishes it — and it draws a line D79 only half-covered: D79
  reserves "irreversible actions" for humans, and this makes the tag push and the
  default-branch change concrete instances. D173 pt 1.
- **The publishers are three slices, not one, because each is gated on a different
  human-owned resource.** Homebrew needs a tap repo the agent cannot create, AUR needs an
  SSH key, and both are therefore config-plus-human-task. Docker is the exception worth
  noting: `ghcr.io` authenticates with the workflow's own `GITHUB_TOKEN` and `docker` is in
  the sandbox, so M5-08 is the one distribution slice an agent can genuinely dry-run
  end-to-end. The constraint that came out of writing them is D173 pt 2 — a publisher
  missing its secret must **skip**, not fail, or a missing token converts a good release
  into a failed one at the moment nothing can be retried.
- **Two scope bullets are already met and now say so.** The keybindings reference is
  generated from the registry and drift-gated by `make check` (M2-01e/D51) — nothing to
  build. And the README "rewrite" has been happening continuously all along, because D68
  makes every leg that moves the install/usage surface update it; what remains is only the
  install section's release half. So there is deliberately **no standalone README slice** —
  each distribution slice documents its own path in the same leg that makes it real, never
  in advance (D173 pt 3).
- **What the sandbox cannot do, recorded rather than discovered later:** neither
  `goreleaser` nor `vhs` is in the image. goreleaser is a Go tool so a leg can likely
  `go install` it — deliberately *not* claimed as verified here, since it was not run — and
  where it cannot, the honest gate is M5-03's CI dry-run job plus config review, not a
  command reported as passing (D79). `vhs` is why M5-09 splits into a tape the agent writes
  and a recording a human makes.
- Decisions: D173 — a release leaves the repo and cannot be reverted, so an agent prepares
