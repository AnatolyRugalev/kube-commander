# 2026-08-15 — STORY-03: `kubecom keys analyze <trace.jsonl>` reads a trace back as findings

- Agent: claude-opus-5 (do-rewrite-leg, interactive session)
- Milestone: M5 (UX-validation line, D268)
- Did: Landed the read side of the instrument, `kubecom keys analyze <trace.jsonl>`, a
  subcommand of the existing `keys` command (per the board note: ride the command, no new
  binary or loose script). It reduces a trace to the four things a UX pass asks (D268 pt 2):
  **unresolved presses** ranked by frequency — keyed by `(key, mode)`, because the same key
  on a different surface is a different dead end, and the surface is what made it one —
  **action counts**, the **longest pauses** (the gaps between consecutive presses, each tied
  to the press that finally came and its surface — the "where did they stop to think" signal
  from STORY-02), and **abandoned sequences** (a run of pending presses that never resolved).
  Sequence completion is judged against the resolved keymap (`keymap.Keymap.Resolve`, a new
  public read-side method: parse a run of key tokens to the binding they complete), so a
  finished `gg` → nav.top is *not* a finding while `g` then `x` is, and a config that rebinds
  a chord is judged by its own meaning. The analysis lives in `internal/keylog/analyze.go`
  beside the writer (`Analyze`, `Read`/`ReadFrom` for JSONL), with the keymap behind a tiny
  `Resolver` interface so the leaf package stays free of the TUI; the command adapts it with
  a three-line `kmResolver`. Two subtle semantics worth keeping: a gap between pending presses
  longer than `keymap.SequenceTimeout` (500 ms) means the timer killed the first run, so the
  presses belong to two abandoned sequences, not one long one; and a nil resolver (no keymap)
  reports *every* pending run as abandoned rather than guessing completion — over-reporting
  beats silently hiding a finding. Filed the STORY-05 human task
  (`vault/human-tasks/2026-08-15-walk-the-stories.md`, Blocks: STORY-06): the instrument is
  now complete, so the act the line exists for — the maintainer walking the five stories — is
  the only thing left before the fold-in.
- Decisions: none — D268 pt 2 already fixes the trace format's constraints and this leg
