- **Why the context switcher takes five slices and not one.** This is the load-bearing
  finding. `run.go` builds **21** cluster-bound `With*` seams, every one a closure over
  the same `*kube.Clients` value fixed at construction — there is no indirection to
  repoint, so "switch context" cannot be written as a swap at all until that changes
  (M4-02, a pure refactor with no behavior change). And the swap itself is a **teardown**:
  the table watch, discovery, a log stream, a search sweep, a drain and the port-forwards
  all belong to the cluster being left, and each one surviving the swap is a correctness
  bug rather than a leak — a live watch from the old cluster streams its rows into the new
  context's table, where a row action then hits the wrong cluster. So the reset lands and
  is tested (M4-03) *before* anything can trigger it, and only then the picker + connect +
  swap (M4-04). M4-05 finishes it: the per-context menu file and last-namespace state are
  resolved once at launch today, so without it a switch lands on the previous cluster's
  namespace. D155 pt 1/2.
- **Where the remaining capabilities plug into existing paths.** Deliberate, and recorded
  so a future leg doesn't build a parallel one. Children resolve to a child `Resource`
  *plus a `ListOptions` scope* rather than a fetched list — `kube.Watch`/`List` already
  take `ListOptions`, so a scoped child table is **live** for free instead of a
  snapshot-only second path; the `spec.nodeName` field selector is safe for Node→Pods
  precisely because the child kind is known to be Pod, which is what made a general field
  selector wrong for cluster search (the SEARCH-04c note). Metrics go over the **dynamic
  client** on `metrics.k8s.io/v1beta1` — `k8s.io/metrics` is not in `go.mod` and this
  needs no new dependency and no kubectl (D2) — and land as a point-in-time overlay on a
  slow ticker joined by object ref, never a watch. Column coloring keys off the **column
  name** (`STATUS`/`READY`/`RESTARTS`), not the kind, because the columns come from the
  server-side Table API and are kubectl-identical (D33), so one rule set covers Pods,
  Nodes and any CRD whose printer uses those names; `styles.Theme` already carries
  `Error`/`Warn`/`Success`, so no palette work is needed. D155 pt 3.
