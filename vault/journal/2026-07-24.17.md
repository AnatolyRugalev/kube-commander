  Backlog), following the D52 kube-primitive-first rhythm the exec (M3-14a/b) and edit
  (M3-15a/b) pairs used. Added `internal/kube/ports.go`: **`Clients.PodPorts`** returns
  the TCP ports a pod declares (`spec.containers[*].ports`, plus native-sidecar
  initContainers — `restartPolicy: Always` — since a proxy/exporter is a prime forward
  target), de-duplicated by number and kept in declaration order; **`Clients.ServicePorts`**
  returns a Service's ports resolved to the **pod-side** number a forward must target,
  since a Service is forwarded via its backing pod (D123/M3-13c) — a numeric `targetPort`
  is used as-is, a **named** one is looked up among the backing pod's declarations, and an
  unset one defaults to the service port (API default). The apimachinery-free
  `Port{Port,Name,Container,ServicePort}` (D33) keeps both numbers so the picker can label
  a choice `80 → 8080` without re-deriving the mapping. Non-TCP declarations are filtered
  at the primitive (port-forward tunnels TCP only), and an unresolvable named target is
  **dropped, not guessed**. Empty results are not errors — declaring ports is optional in
  the API, so the picker must stay an affordance over the existing free-text prompt. → D137.
  Chose to always fetch the backing pod when a ref is given rather than only for named
  targets: the "skip the Get when all targets are numeric" optimization saved one cheap API
  call but left numeric choices unlabelled while named ones were labelled — inconsistent
  picker rows for no real gain.
