# 2026-07-19 — M2-03: lipgloss theme + style set

- Agent: claude-opus (Opus 4.8), autonomous leg
- Milestone: M2
- Did: Landed `internal/tui/styles` — the app's single source of visual truth.
  A `Theme` is a struct of named, semantic `color.Color` fields (Foreground,
  Subtle, Primary, Selection(+Fg), Border(+Focus), Header, StatusBar fg/bg,
  Error/Warn/Success) with no styling; `New(Theme) Styles` is the one place a
  color becomes a `lipgloss.Style`, yielding the roles components render through
  (App, Subtle, Selection, Header, Pane/PaneFocus with a rounded border accented
  on focus, StatusBar, Error/Warn/Success, Spinner). `DefaultTheme()` is a
  dark-friendly truecolor palette with a blue accent (nod to the original);
  `Default()` = `New(DefaultTheme())`. Everything is pure, immutable, copyable
  data — no shared mutable UI state, no global renderer touched (principle 1).
  Components ask for a role, never `lipgloss.Color`/`NewStyle` directly, so a
  future theme picker (M4/D6) just swaps the Theme. Foundation for M2-04 onward.
- Decisions: D54 — styles package = Theme (named colors) → Styles (derived
  lipgloss); named roles not literals; pure/immutable/copyable; DefaultTheme
  truecolor+blue, downsampled at write time (no AdaptiveColor in v2); lipgloss v2
  promoted indirect→direct (no version change, go.sum untouched).
