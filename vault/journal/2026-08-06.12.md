## The name existed the whole time; the palette was throwing it away

`paletteVerbItems` has read `a.Describe()` since PAL-02, and the doc comment above it is
proud of the fact: the label is the registry's own description, so "an entry cannot
describe itself differently from its key". That reasoning is sound and it is why the fix is
additive. What it missed is that `a` — `ns.switch`, `theme.switch`, `app.quit` — is *also*
in hand at that line, is the name the rest of kubecom uses for the command (the `keys:` map
in `config.yaml`, `docs/keybindings.md`, the `?` overlay's grouping), and was the one piece
of the entry the reader never got to see.

So the diff is not "add a second field to look up". It is one `Name:` per constructed item,
and the interesting work is entirely in the picker's row renderer.

That also settled the naming question the feedback did not have to answer. The palette's
argument verbs each carry a *word* — `resource`, `namespace`, `theme` — and it was tempting
to show that, because it is what the prompt reads (`:namespace `) and it is shorter. It is
the wrong choice twice over: only six of the fourteen verbs have one, so eight rows would
need a word invented for them, and the word is deliberately *not* the id (`:namespace ` for
`ns.switch`), so a reader who learned the column would then be unable to find the command
in their own config. D237 pt 2 writes the rule as "the id it already has elsewhere" for that
reason — the column's value is that it is not a new vocabulary.

Row verbs are the one place that rule needed a second reading. Their ids (`delete`,
`rolloutRestart`) are not keymap actions — several are menu-only and have no key at all —
but they are exactly the words the `:action ` line takes (`:action delete`, D210), so the
column shows the name that line already accepts.

## Matching the name is what makes the column more than decoration

Showing `ns.switch` and then not matching it would have been a trap: the first thing a
reader does with a visible identifier is type it, and `ns.sw` is **not** a subsequence of
"Switch namespace" — there is no `.` in the label — so it would have matched nothing at all.
The name joins the label and the aliases in `matchItem`, scored by the best of them, which
is the rule CRD-PIN-04 already established for aliases.

The difference worth stating (and D237 pt 1 does) is that a Name is *shown* while an alias
is deliberately hidden, and neither is the identity: the Label still is. That is what let
this land without touching `cmdByLabel`, `palRowByLabel`, `resByLabel`, `themeByLabel` or
any of the `SelectedMsg` routing — the maps are keyed by exactly what they were keyed by
before, and the confirm marker (`Delete (confirm)`, D228) is still part of the label rather
than something the new column has an opinion about.

## The bug the column exposed: a picker row could always wrap, and now one did

The first working version rendered correctly and cost the modal an item. `mouse.toggle`'s
description is "Toggle mouse capture (off = select text to copy)" — 47 cells, which fitted
the 58-cell list on its own and does not fit once a 16-cell name column and its gap are in
front of it. `lipgloss.Style.Width()` **wraps**; `MaxWidth` is applied to the already-wrapped
block, so the row became two lines, the delegate's `Height() == 1` contract was quietly
false, and `app.quit` fell off the bottom of the box.

This was never specific to names. Any label longer than the list width has always wrapped
this way — no picker had one, so nothing ever showed it. The fix is to cut the composed line
to the list width with `ansi.Truncate` (ANSI-aware, so the styled name segment keeps its
escape sequences) *before* the style is applied, and to mark the cut with `…` so a clipped
description is legible as clipped rather than as a sentence that ends strangely.

It is the same failure shape BOX-03 recorded in D220 pt 1 — a component whose `View()`
string is complete while the composited frame is short — one level further in, and it is
why D237 pt 3 states it as a constraint rather than leaving it as a fix. The test that
would have caught it is not a unit test on the row: it is reading the frame and counting
what is on it.

## Measuring the column over the visible rows, not the item set

`setVisible` re-measures the name column each time the list is rebuilt, which means the
column follows the query: `:` shows a 16-cell gutter because `resources.switch` is on
screen, and typing `quit` shrinks it to 8 and gives the eight cells back to the
description. Measuring over `m.all` instead would have been one line shorter and would hold
a gutter for rows the reader cannot see — on the narrow modal that is exactly where the
width is worth the most.

The cost is that the delegate now has two inputs (styles, column width) and is replaced
whenever either changes, so it is built in exactly one place. `TestNameSurvivesARestyle`
exists because the obvious mistake — `SetStyles` constructing `itemDelegate{styles: s}`
directly, as it did before this leg — silently resets the column to zero and un-aligns an
open palette on a theme change.

## What is not fixed, and why it is not this leg

The palette lists 14 verbs plus the selected row's actions, and the modal is capped at 20
rows and 60 columns (`modalMaxWidth`). The name column spends 18 of those columns, which is
why `mouse.toggle`'s description is now the one row that ends in `…`. Widening the modal
would fix it and would change the geometry of **every** picker in the app — the namespace
switcher, the context list, the container and port pickers — for the benefit of one row in
one of them. That is a legitimate item and not a rider on this one; if the truncation turns
out to be what the reader notices, it is a width change to the modal constants, in its own
leg, with the other five pickers looked at.
