# 2026-08-15 — STORY-02: `--keylog` records what was actually pressed

- Agent: claude-opus-5 (do-rewrite-leg, interactive session)
- Milestone: M5 (UX-validation line, D268)
- Did: `--keylog <file>` (or `$KUBECOM_KEYLOG`) appends one JSON object per keypress:
  the key, the surface it was routed to, and the action it resolved to. Off unless asked
  for, documented in the README, and shipped in the binary — the maintainer's call over a
  build-tagged recorder (D268 pt 2), because the binary a user reports a UX problem *from*
  is the release binary. `internal/keylog` is the writer (JSONL so a trace is tailable
  while the session producing it still runs; appends, so walking a story twice does not
  erase the first trace; a write failure reports once and goes quiet, because losing a
  trace must never cost the run it was recording). The shell side is `internal/tui/
  keylog.go`: one `keyMode()` ladder now *is* the routing ladder at the top of Update's
  `KeyPressMsg` arm, so the mode written into a trace cannot disagree with the surface that
  handled the press — the previous six sequential `if` returns became one `switch` on the
  mode. Records are written before the press is handled, so the keypress that quit or
  wedged a session is in the trace that has to explain it. Two fields keep the headline
  signal clean: `text` marks a surface where an empty action is expected (typed characters
  are not dead ends), and `pending` marks the first key of a sequence (`g` of `gg`) as
  resolved-to-nothing-*yet*. A dead end is therefore `action == "" && !text && !pending`.
- Decisions: none — D268 pt 2 already fixes this feature's constraints (ships, off by
  default, the unresolved press is the point, the privacy note rides the docs) and this leg
  implements them. Mode *values* are part of the trace format, which is noted in the code
  where an analyser will read it rather than as a new Dn.
- Files: internal/keylog/{keylog.go,keylog_test.go}, internal/tui/{keylog.go,keylog_test.go},
  internal/tui/app.go, cmd/kubecom/{main.go,run.go,run_test.go}, README.md,
  vault/tasks/board.md, this entry.
- Verify: build ✓ · test ✓ · vet ✓ · lint ✓ — `make check` green. Runtime, against the
  live `k3d-kubecom-test` cluster and the real binary (D68): driven through vhs, pressing
  `j`, `x`, `g`, `/`, `web`, esc, `q`. The trace came out exactly as designed — `j` →
  `nav.down`, **`x` → no action, no text, no pending (the dead end)**, `g` → pending, `/` →
  `app.filter`, `w`/`e`/`b` → filter text, `q` → `app.quit`. Two test-time findings worth
  keeping: `openFilter` requires `hasCurrent`, so a bare model records the *absence* of a
  filter surface and proves nothing (the tests build a browsing model); and the record is
  stamped at the press rather than at the sink, since the gap between two keys is the
  measurement and must not include however long a writer took.
