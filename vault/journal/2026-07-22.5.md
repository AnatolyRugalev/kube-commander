# 2026-07-22 — M2-12a: legacy config migration (parse + report primitive)

- Agent: claude-opus-4-8
- Milestone: M2
- Did: Split M2-12 (mirroring the M2-11a primitive-first rhythm) and took the first
  slice — the migration primitive, no app wiring. Added `internal/config/migrate.go`:
  `LegacyPath()` (`~/.kubecom.yaml`) and `Migrate(io.Reader) (*Config, []string, error)`.
  On inspecting the old shape (protobuf-yaml `pb.Config` = `menu` + `currentTheme`/
  `themes`) I found a faithful field-for-field migration is **impossible offline**:
  the legacy `menu` stored `group`+`kind` but no `version`/`resource` (which the v1
  `MenuResource` requires and only discovery resolves), and v1 has no runtime theming.
  So `Migrate` recognises the legacy file, returns the **zero Config** (nothing maps —
  keys never existed in it), and emits human-readable **notes** on what the user must
  redo by hand (legacy menu resources → a per-context menu file; themes → dropped).
  Parsing is lenient (non-strict) so leftover theme detail is ignored and a legacy
  file never blocks start (principle 3); only unparseable YAML errors. → D92.
- Decisions: D92 — legacy migration is detect-and-report, not a field port; no leg
  may auto-map the old menu/themes or write a `MenuConfig` with blank version/resource.
