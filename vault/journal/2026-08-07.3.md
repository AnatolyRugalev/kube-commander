## The complaint was structural, and so was the fix — but only after an inventory

The feedback's own diagnosis was precise: `## Usage` was lines 139–423, "everything kubecom
can do in there in the order it happened to get built, with bolded lead-ins doing the work
that headings should be doing". It also pointed at the one thing that makes this leg
possible in one sitting: `docs/keybindings.md` is generated from the action registry and is
"the most honest inventory of the capability set we have".

Reading that inventory against the README is what turned this from a formatting job into a
content one. Roughly forty actions are registered. The README documented most of them and
was silent on several the reader would want: `s`/`S` (sort), `D` (describe — mentioned only
in passing, as the thing that "still opens in the shared centered viewer"), `r`/`c` (reveal
and copy a secret), exec shell, `F` and the port-forward panel, and the kind-specific verbs
— scale, rollout restart, cordon/uncordon/drain, suspend/resume — which appeared nowhere
except as a list of palette entries in a sentence about the palette.

That is the accretion failure in its purest form: those capabilities each landed in a leg
whose *own* README paragraph was about something else (the palette, the viewer, the
container image), so the capability got a clause instead of a home. The restructure makes
the omission visible, because a heading called "Acting on objects" with no `Scale` under it
is obviously wrong in a way that a missing paragraph in a 290-line section is not.

So the action set is now a **table** keyed by kind, generated from nothing but read against
`rowActions` in `internal/tui/rowaction.go`. It is the one place where a table beats prose:
"which of these can I do to a Node" is a lookup, and the registry's own `applies` predicate
is the answer.

## What moved out, and the test for it

D241 pt 2 states the rule I used: if a paragraph is *looked up* rather than read, it is
reference. Applying that mechanically:

- Install went to `docs/install.md` — three variants, the `@v1` semver explainer, the
  Gatekeeper note, the AUR rename warning, the distroless image's two limits. The README
  keeps five lines and a `git clone -b v1` block, which is the only path that works today.
- Configuration went to `docs/configuration.md` — the config file, the theme table, the
  per-context menu YAML, what `*` writes and where, the remembered namespace, and the 2020
  migration. The README keeps a four-line `config.yaml` sample, because "it needs no
  configuration, and here is what configuring it looks like" is a *narrative* claim.

The capability prose stayed in the README. That is the line: `T` switches theme and the
pick is written back to `config.yaml` (narrative — it is a thing you do); the six palette
names, their upstream attribution and the reason none of them is light (reference — it is a
thing you look up). Both halves used to be one paragraph.

## The move nearly retired three guards, silently

`internal/version` has had three guards since the packaging legs: the README's `brew tap`
line must name a tap some cask in `.goreleaser.yml` publishes to, its `` `kubecom-bin` ``
mention must be a package the AUR pipe emits, and its `ghcr.io/…` reference must be an
image the docker config pushes. Each is written to be **dormant-tolerant** — no install
path documented yet, return early — because they were added before the paths existed.

Dormant-tolerant plus keyed-on-one-file is a trap, and I walked into it before noticing:
moving the install section to `docs/install.md` would have left all three passing, forever,
having found nothing to check. Nothing fails; the coverage just evaporates, and the failure
is invisible in exactly the way D241 pt 3 now names. The fix is small (`installDocs` is a
two-element slice and `installDocText` concatenates it), but the rule is the part worth
keeping: name the **set** a claim may live in, not the file it happens to live in today.

Same class of thing, one layer down: `internal/config/migrate.go` tells a migrating 2020
user to "see README: Per-context menu", which after this leg pointed at a heading that no
longer exists. No test guards that string — it is a runtime notice, not a doc — so it was
found by grepping for `README` across the tree rather than by `make check`. Worth stating
for the next leg that moves a section: the docs are cross-referenced from **Go strings and
from `vault/`**, not only from other Markdown.

## Three human-task files gave instructions against a section that moved

`2026-07-30-homebrew-tap-access` and `2026-07-30-aur-package-access` each end with "replace
this paragraph under [Install](../../README.md#install) with the real path", and step 3 of
`2026-07-30-first-release-tag` lists the post-tag README edits. Those are instructions to a
human (or to the leg that folds the result back in) about a file that just changed shape.

Updating them is not tidiness. A human task that is *wrong about where the edit goes* is
worse than one that is vague, because it will be followed: the likely outcome is the
Homebrew paragraph being re-added to the README, next to the pointer that says the install
paths live in `docs/install.md`, which is precisely the accretion this leg undid. They now
name the `docs/install.md` bullet, and the tag task notes that the `@v1` explainer moved
with it.

## What DOC-02 is for, and why it is not this leg

The paragraphs are, with a few merges, the ones that were there. They are still written in
the voice of the leg that added them — "Press `X` (`action.id`, rebindable) to …" opening
nearly every one, several arguing a design decision the reader never asked about (why the
fuzzy cap exists, why `$VISUAL` is consulted, why the timestamps are off by default). Under
a heading that already says what the section is about, most of those openings are dead
weight and some of the arguments belong in the decisions log they came from.

I did not do that here for the reason the feedback itself gives — "a 576-line rewrite in one
commit is not reviewable". This diff is already a whole-file rewrite plus two new documents;
folding a sentence-level pass into it would make the structural change impossible to read
against the old file. DOC-02 has the board entry with the specifics, including the one
instruction that matters: the failure-mode paragraphs ("A resource that won't list", "An
expired credential plugin") are the ones the feedback explicitly asked to keep, and they
earn their length.
