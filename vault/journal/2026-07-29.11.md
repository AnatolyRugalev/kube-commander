# 2026-07-29 — LOGS-06: init and ephemeral containers in the logs picker

- Agent: claude-opus (do-rewrite-leg)
- Milestone: M3 (LOGS line, feedback-driven)
- Did: Drained feedback `2026-07-29-logs-init-containers`. `kube.PodContainers` returned
  only `spec.containers`, so an init container's logs were unreachable — exactly the logs
  wanted when the pod never got past init. It now returns `[]kube.Container` (regular,
  then init, then ephemeral, each in spec order, tagged with a `ContainerKind`), the shell
  narrows that set by purpose (`ctrPurpose.offer`: logs takes all three, exec drops the
  init containers — nothing to attach to once they terminate), and the picker marks a
  non-regular row `name (init)` / `name (ephemeral)`, resolving the pick back through a
  `ctrByLabel` map (the D65 pattern) so a label never reaches the kube layer as a name.
  Consequence accepted in D161 pt 3: a pod with one regular container beside an init one
  now prompts for logs where it used to stream straight through — regular containers sort
  first, so `L`+`enter` still lands on the pod's main container.
- Decisions: D161 — a pod's containers are all of them, classified; the picker offers what
  the purpose can act on, and a non-regular container is always marked.
