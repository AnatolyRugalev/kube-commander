# 2026-07-19 — M1-07d: reconnecting/resuming follow logs

- Agent: claude-opus (Opus 4.8), autonomous leg
- Milestone: M1
- Did: Hardened `Clients.Logs` so a **Follow** stream survives a transient
  transport drop, extending the M1-07c single-connection core (`internal/kube/logs.go`)
  into a reconnecting loop à la watch (D34). `runLogStream` now dispatches on
  `follow`: the non-follow path is unchanged; `followLogStream` reopens on a drop.
  Logs have no resourceVersion, so Follow forces server-side `Timestamps` on the
  wire (each raw line `"<RFC3339Nano> <content>"`), tracks the last-seen line's
  timestamp, and on reconnect sets `SinceTime` to it. `SinceTime` is second-granular,
  so the server re-serves the whole last second; the new `logResumer` holds the raw
  lines already delivered in that second and drops the re-serves, delivering only
  genuinely-new lines (incl. ones missed during the drop), then clears the window on
  the next second. Timestamps stripped before delivery unless `opts.Timestamps`.
  Clean EOF (bufio.Scanner reports nil at io.EOF — the container's log ended) stops;
  any other read error reconnects. First open failure is terminal; a reconnect
  failure is transient (silent backoff+retry bounded by ctx) since a `LogEvent{Err}`
  is terminal by contract.
- Decisions: D44 — force wire timestamps to anchor the resume, resume via `SinceTime`,
