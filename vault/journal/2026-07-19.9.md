- Did: Landed `internal/kube/errors.go` — `Classify(err error) ErrorKind`, the
  "graceful, typed errors, never panic on bad ns/context" exit clause (#86,
  principle 3). The kube layer already returns every error wrapped
  (`fmt.Errorf(... %w)`), so instead of rewiring ~40 error sites into constructed
  typed errors, M1-09 adds one classifier that **walks the existing wrap chain**
  and maps it to a small `ErrorKind` taxonomy the M2 TUI switches on to degrade a
  single feature instead of crashing: `KindNotFound`/`AlreadyExists`/`Conflict`/
  `Forbidden`/`Unauthorized`/`Invalid`/`Timeout`/`Unreachable`/`BadContext`/
  `Unknown` (+ a stable-token `String()`). apierrors `Is*` predicates already
  unwrap `%w` to the embedded `*StatusError`; transport failures (dial refused,
  DNS, TLS) arrive as `*url.Error`/`net.Error` and map to `Unreachable`;
  `context.DeadlineExceeded` → `Timeout`. **Bad-context** is layer-tagged, not
  string-matched: the common `--context nope` case is a plain
  `fmt.Errorf("context %q does not exist")` inside clientcmd that **no clientcmd
  predicate matches**, so `RESTConfig` now wraps its errors with an unexported
  `errBadContext` sentinel (dual-`%w`) and `Classify` keys off `errors.Is` — the
  clientcmd predicates stay only as a secondary net. No call site behaviour
  changes; the underlying error stays reachable via `errors.Is`/`As`.
- Decisions: D46 — classify the wrapped chain (no rewiring); taxonomy set;
  apierrors predicates walk `%w`; transport via `*url.Error`/`net.Error`;
  `RESTConfig` tags bad-context with `errBadContext` because clientcmd exposes no
  predicate for an override-context miss.
