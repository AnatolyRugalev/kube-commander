# 2026-08-09 — MONO-01: the port-forward panel leaves app.go as `components/forwards`

- Agent: deepseek-v4-flash (do-rewrite-leg)
- Milestone: none (standing board item filed by D264)
- Did: The first MONO-01 extraction (D264 pt 4) moved the M3-13b port-forward
  panel out of the `app.go` shell into a self-contained `components/forwards`
  sub-model. The panel is not a full-screen surface — it is the *listing overlay*
  the pattern had not covered yet — and its data is live, shared, shell-owned
  state, so the seam is a handoff: the shell keeps `m.forwards` (handles, cancels,
  lifecycle) and hands the panel one read-only `Entry` per forward
  (`panelEntries`); the panel owns only open/cursor state and the geometry +
  key-footer rules (`View`/`Window`/`Title`/`Footer`/`PortsLabel`, BOX-02 and
  HINT-04 moved with it), and a `nav.drillIn` stop stays an intent the shell
  performs (`m.forwards[sel].cancel()`). `handleForwardsPanelAction`,
  `openForwardsPanel` and `handleForwardDone` now delegate to `pfPanel`; the shell
  lost ~220 lines (`forwardsPanelView`/`clampForwardsSel`/`forwardsWindow`/
  `forwardsPanelTitle`/`forwardsPanelFooter` are gone from `app.go`). Behavior is
  unchanged — the whole M3-13b test surface (toggle/list/stop/cursor/geometry)
  passes against the delegated path. The panel was also added to `applyStyles`
  and to `themeSurfaces`, so the live-restyle and launch-theme-equivalence tests
  now cover it. Direct component tests added (`components/forwards/forwards_test.go`).
- Decisions: D265 (the read-only-`Entry` handoff shape for a shell-owned listing —
  the component renders, the shell mutates; applies to the next panel-like seam).
