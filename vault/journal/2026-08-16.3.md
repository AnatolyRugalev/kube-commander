# 2026-08-16 — STORY-06e: the instrument tells the truth — the recorder writes the confirm modal's resolved action, and the analyzer reports text-surface presses separately

- Agent: opencode (do-rewrite-leg, interactive session)
- Milestone: M5 (UX-validation line, D268)
- Did: The two mirror-image instrument fixes, exactly as the walk's findings named
  them. **(1) Recorder (`internal/tui/app.go`):** every non-browse press used to be
  written with a blank action, so a confirm modal's *handled* `esc`/`y`/`enter`/`n`
  — which `routeModalConfirmKey` resolves in the confirm context (D132) — read back
  as dead ends; the S02 trace's `esc 2 modal-confirm` "unresolved presses" were
  both declines that worked. The confirm mode now resolves the action at record
  time via a shared `confirmResolved` (ConfirmAction first, then the browse
  fallback so `app.quit` still dismisses), so a handled accept/decline is written
  with the action it ran — while an unhandled confirm key stays a dead end (the
  modal is not a text surface). **(2) Analyzer (`internal/keylog/analyze.go`,
  `cmd/kubecom/keys.go`):** `Analyze` counted dead ends only when `!Text &&
  !Pending`, so a text-surface press that resolved to nothing was invisible — the
  picker's 4 dead `j`s of the S01 walk were exactly that. `Report` gains a
  `TextPresses` section (ranked by frequency, like dead ends) tallied from
  `Text` presses with no action, rendered by `printAnalyze` as "presses on text
  surfaces — typed, or a reach the surface swallowed". The dead-end predicate is
  unchanged; text presses just tally into their own bucket, so ordinary typing
  does not flood the dead-end count and the S01 finding is no longer hidden.
  `rankedDead` generalised to `rankedKeyMode` (the two sections share a shape).
  README and stories/README now list the text-surface section among the findings.
