# 2026-07-28 — SEARCH-04a: all-kinds scope widen for cluster search

- Agent: claude-opus-5
- Milestone: M3
- Did: Split SEARCH-04 D52-style into **04a** (kind scope), **04b** (namespace scope) and
  **04c** (richer matching), and took the first. `search.allKinds` (`ctrl+a`) swaps the
  curated eleven-kind default for every kind discovery found and re-runs the query that is
  already typed; the header says `all kinds` while it is on. The same leg bounded
  `kube.Search`'s fan-out to eight concurrent lists, because the widen is what makes an
  unbounded one dangerous. → D149.
- **The bound is not a nicety, it is the widen's precondition.** D131 pt 2 asked for a
  widen that is "rate-limit-aware on big clusters", and the reason that phrase is in the
  decision is that `kube.Search` spawns one goroutine per kind and lists immediately.
  Eleven curated kinds is nothing; a hundred-plus discovered kinds — which is an ordinary
  cluster once a few operators are installed — is a hundred-plus simultaneous LISTs, and
  client-go applies **no** client-side rate limit unless `rest.Config.QPS` is set, which
  this project never sets. So the widen without the bound would have been a keystroke that
  can hurt a cluster. A semaphore in `searchRows` costs the curated path literally nothing
  (its kinds never queue) and turns the widen into a steady stream.
- The bound had one interaction worth a test of its own. The cap cancels the sweep while
  most kinds are still *queued for a slot*, and the contract says exactly one
  `SearchKindDone` per requested kind (D142 pt 2) — so the acquire has to be a
  `select` on the semaphore **and** `ctx.Done()`, with the deferred done-event outside it.
  Get that wrong and every capped wide search leaves the view's "searching N/M kinds…"
  stuck short of M, which reads as a hang. Both halves are tested: one test parks every
  List and proves only eight are ever in flight (it fails against the pre-change code),
  the other trips the cap with most kinds queued and proves all of them still report done,
  none marked `Failed`.
- **Where the widen lives is the design.** There is no widen flag anywhere in
  `internal/kube` — `CommonSearchResources` is a filter, and widening is the caller
  declining to call it. The view holds the boolean and announces it; the wiring turns it
  into a kind set, because it is the side that knows what discovery found. That is why the
  component tests can assert the whole toggle without a client and the app tests can assert
  the kind set without a view.
- Three calls that shape how it feels. (1) **The widen resets on every open.** It survives
  typing and refining within one visit — the reader chose it for *this* search — but
  `ctrl+s` always starts curated. A sticky expensive mode is the fast-cold-start failure
  (D8/principle 4) in miniature: a choice made once, paid forever, invisibly. (2) **A scope
  change invalidates results exactly as a query change does** — hits, progress and the cap
  dropped, the in-flight fan-out cancelled and superseded, the same debounce. A result set
  means *query × scope*, so a count carried across the toggle is a lie about the header
  above it; and keeping the debounce means a held-down toggle cannot queue one full-cluster
  sweep per key repeat. `handleSearchQueryChanged` and `handleSearchScopeChanged` are now
  two names for one `restartSearch`. (3) **Only the widened state is named.** D146's rule
  applied to scope: `all kinds` appears when on, nothing when off. The header is clipped
  from the right and the progress line's `N/M kinds` already sizes the scope.
- The hint bar is where this leg differs from the last three, and deliberately. LOGS-04a/b
  argued their toggles into `?`-only because they self-announce and the logs hint line is
  full. The widen does *not* self-announce: with it off the header says nothing, so a
  reader staring at `no matches` has no way to learn the search was curated. And
  `HelpSearch` is the app's shortest context — four entries. So this one is hinted, and the
  rule that produced both answers is the same one.
- `ctrl+a` costs the query field its readline start-of-line binding. Worth noting rather
  than agonising over: the field had already lost `home` to `nav.top`, and a search query
  is one short line. Any no-text chord was forced — a plain `a` types (D140 pt 1), which
  has its own test.
- Decisions: D149 — an expensive opt-in scope resets per visit; a scope change invalidates
  results exactly as a query change does; name the widened state, not the default; bound
  the fan-out in the search primitive, not in the toggle that makes it matter.
