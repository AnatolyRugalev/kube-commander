# 2026-07-19 — M2-01b: multi-key sequences + timeout resolution

- Did: Extended the M2-01a keymap core with multi-key sequences (the vim `gg` →
  `nav.top` case, D10) and their stateful, timeout-driven resolution. A binding is
  now a `seq` (`[]chord`, length ≥ 1), so single chords and sequences share one
  model: `parseSequence` accepts a lone chord, the vim concatenated form (`gg`),
  and a space-separated form (`g g`, `ctrl+w k`); `seq.String()` round-trips.
  `DefaultKeymap` sets `nav.top` to `{"gg", "home"}` (vim sequence + single-key
  fallback). The `Keymap` stays immutable and gained two derived indexes
  (`prefix`/`extends`) plus the exact `bySeq` map; a new `Sequencer` holds the only
  mutable input state (the buffered prefix) and is driven key-by-key from the
  (future) update loop: `Input` returns `ResultAction`/`ResultPending`/`ResultNone`,
  a non-continuing key abandons the buffer and is retried alone, and `Timeout`
  fires a buffered prefix only if it's itself a complete binding. **The keymap
  package runs no timer** — `ResultPending` tells the model to schedule a
  `tea.Tick(SequenceTimeout)` and call `Timeout()` when it fires, keeping the
  package pure/hermetic (principle 1, no goroutines/clock). `Keymap.Action(key)`
  stays as the single-key resolver for non-buffering views (modals/pickers).
- Decisions: D48 — sequences unify with single chords; stateful matching in a

  var, 500ms); a prefix that is also a complete binding pends then fires on timeout;
  pgdn/pgup stay half-page only (the board's full-page-fallback note would collide).
