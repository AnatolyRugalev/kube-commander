# 2026-08-20 — STORY-06k-2: the search result preview

- Agent: claude-opus (do-rewrite-leg)
- Milestone: M5 (UX-validation line, D268)
- Did: Folded in `2026-08-15-search-result-preview.md`, the S05 high-priority finding
  that a result list showing only identity makes the reader open the wrong hit and
  search again ("did the results tell you enough to pick the right one without opening
  each" — the answer was no). Second and last slice of STORY-06k, so 06k is closed.
  Two halves. **kube**: `SearchHit` gains `Columns` and `Cells` — the object's
  server-printed row and the column set it sat under. That row was already listed to
  match the name, so carrying it is free; the alternative was a fetch per highlighted
  row, which puts a cluster round-trip on every `j`. It supersedes the *rationale* of
  D276 pt 2 ("a search hit carries no printed cells because drilling re-lists"), not its
  constraint: drilling in still re-lists and watches the real table — the cells are for
  deciding *whether* to drill in. Columns are shared by every hit of a kind (never
  mutated) and a short row is normal, so cells are indexed defensively.
  **searchview**: a two-line footer under the result list describing the *highlighted*
  hit — `previewIdentity` (kind · apiVersion · namespace/name, the apiVersion being the
  piece the row cannot show and the one that separates two same-named kinds from
  different groups) over `previewDetail` (the printed cells as `COLUMN: value` pairs in
  the server's own order, NAME dropped because the line above it *is* the name, empty
  values dropped because a column the server printed nothing into spends width saying
  nothing). `previewHeight` is subtracted in `innerSize` unconditionally, so the list is
  sized against the block whether or not there are hits and the rows never shift under
  the cursor the moment the first hit arrives; a kind that printed no cells keeps the
  height with a blank second line; with no hits nothing is rendered at all (the hint
  already occupies the list's place). Identity paints through `styles.Accent`, the
  detail through `styles.Subtle`. `table.FormatCell` does the cell formatting, so the
  preview and the browse table can never disagree about a value.
- Decisions: **D283** — a search hit carries the row it was matched in, the search view
  previews it in a height-reserved two-line footer, and a preview is data the surface
  already holds, never a fetch (a later leg enriching it must keep a cursor movement
  request-free). Supersedes D276 pt 2's no-cells rationale.
