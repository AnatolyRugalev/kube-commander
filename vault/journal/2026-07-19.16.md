# 2026-07-19 — M2-02: TUI message types + channel→msg pumps

- Agent: claude-opus (Opus 4.8), autonomous leg
- Milestone: M2
- Did: Landed `internal/tui/msg.go` — the boundary between the concurrent `kube`
  layer (which returns work on channels) and the single-threaded Bubble Tea update
  loop (which consumes `tea.Msg`). Message types: `ResourceEventMsg` (a
  `kube.WatchEvent` data delta carried verbatim), `WatchClosedMsg` (terminal
  watch-channel close), `DiscoveryReadyMsg` (the whole `kube.DiscoveryResult`
  reconcile signal), a generic classified `ErrorMsg{Context,Err,Kind}` with
  `NewErrorMsg` fixing `Kind = kube.Classify(Err)`, plus cross-component selection
  msgs (`ResourceSelectedMsg`, `RowSelectedMsg`). The **pumps** are `tea.Cmd`
  adapters that read **exactly one** item from a kube channel and return it as a
  msg: `watchPump` (delta→`ResourceEventMsg`, watch ERROR→`ErrorMsg`,
  closed→`WatchClosedMsg`) and `discoveryPump` (always `DiscoveryReadyMsg`,
  carrying a total failure via `Result.Err` rather than swapping in a generic
  error; closed-empty→nil). One receive per Cmd keeps `Update` from ever blocking
  on more than a single receive; the model re-issues the pump to pull the next
  item and stops on `WatchClosedMsg`. Size is Bubble Tea's own `tea.WindowSizeMsg`.
  No UI yet, no shared mutable state (principle 1) — pure adapters.
- Decisions: D53 — one-item channel→msg pumps; watch ERROR bridged to `ErrorMsg`;
  closed watch → explicit `WatchClosedMsg` (not nil, to stop re-pumping a closed
  channel); discovery total failure kept inside `DiscoveryReadyMsg`; `ErrorMsg`
  classifies once at construction; size via `tea.WindowSizeMsg`.
