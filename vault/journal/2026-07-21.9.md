# 2026-07-21 — FB-menu-item-states: menu marks the opened resource distinctly from the cursor

- Agent: claude (Opus 4.8), autonomous leg
- Milestone: M2
- Did: Addressed the oldest dogfood feedback (`2026-07-21-05-menu-two-item-states`,
  normal). The left menu conflated two things: the **nav cursor** (where the
  selection sits as you move) and the **opened/active** resource (whose table fills
  the right pane). Now they are two independent visual states — with the table
  focused and Pods open, the menu still shows Pods marked as active while the cursor
  can sit anywhere. The active resource is tracked in the menu by **GVR** (not index,
  so it survives Reconcile appending CRDs), set from the app's `selectResource` via a
  new `menu.SetActive`/`ClearActive`. Rendering: the active row is prefixed with a
  `▸ ` marker (two columns, exactly the width of the plain `  ` item indent it
  replaces, so nothing shifts) and, when it is not also the cursor, drawn in a new
  accented `styles.Accent` (Primary fg, bold, no bar). The cursor keeps its
  full-width Selection bar; when a row is both cursor and active the marker and the
  bar compose. The `▸` marker is distinct from the namespace seam's `▾` and from the
  scrollbar/border glyphs, so a rendered view stays scannable.
- Decisions: none (no new binding constraint — the two-state rendering and the `▸ `
  marker are local UX choices, recorded here per D67; `styles.Accent` is an additive
  general "accented emphasised text" role). Deleted the feedback file.
