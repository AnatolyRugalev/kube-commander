- Did: Closed the port-forward feedback line (`2026-07-24-port-forward-picker-and-local-port`
  part 2) by giving the **local** end of a forward a surface. Two new registered actions
  (D11), both meaningful only while the port picker is up: **`forwards.freeLocal` (`0`)**
  forwards the highlighted port immediately with the leading-colon spec `:<remote>`, so
  the OS assigns a free local port (the one-keystroke escape from a local clash), and
  **`forwards.localPort` (`p`)** opens a prompt seeded with the remote number whose blank
  value means the same free port, otherwise submitting `<local>:<remote>`. `enter` is
  untouched — it still forwards local = remote (D138 pt 2's real content). The root
  handles both while `portPicker` is active so the shared picker component stays generic
  (it knows nothing about ports); they are inert everywhere else, exactly like
  `logs.follow` / `secret.reveal` outside their viewers.
- Also **removed the single-declared-port fast path** (D139 supersedes D138 pt 2): the
  picker is the only surface carrying these gestures, so a pod declaring exactly one port
  whose local number was already taken could never reach a different local port — every
  invocation re-forwarded the same clashing spec and re-failed. A one-row picker is still
  one keystroke. And while checking client-go's parse I found the D130 hint's `:0`
  suggestion is **invalid**: `parsePorts` reads the half after the colon as the *remote*
  port and rejects 0 ("remote port must be > 0"), so `:0` could never have worked. The
  bind hint now offers only `:<remote>` (and stays generic when every spec already
  auto-assigns), and the picker title advertises the gestures by their *resolved* keys
  (`Port-forward port · p local · 0 free`) since a modal has no hint bar.
- Decisions: D139 — every declared port goes through the picker (superseding D138 pt 2's
  fast path); the local side is opt-in (`enter` local=remote, `0` free, `p` prompt), never
  a mandatory prompt; the free-local spec is `:<remote>`, never `:0`; a modal advertises
  its own gestures in its title, read from the keymap.
