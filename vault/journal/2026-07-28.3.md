# 2026-07-28 — LOGS-04b: timestamps toggle in the logs view

- Agent: claude-opus-5
- Milestone: M3
- Did: Took the last LOGS slice. `logs.timestamps` (`t`) draws each log line's server
  timestamp ahead of its message. The board's framing of the leg turned out to be stale in
  the one way that mattered — it said `kube.LogOptions` had no `Timestamps` field and the
  leg would need to add one; it has had it since M1-07. That changed the question from
  "add a flag and decide restream-vs-display" to just the second half, and the answer fell
  out of what the kube layer was already doing. → D148.
- **The toggle is free because the wire already carries it.** A *following* stream forces
  server timestamps on regardless (D34: the resumer needs them to anchor a reconnect) and
  then strips them again before delivery unless the caller asked. The TUI only ever opens
  logs with `Follow: true`. So setting `Timestamps: true` costs nothing on the network and
  nothing on the server — it just stops the strip. That makes the display-vs-restream
  trade one-sided: a restream would drop the buffer, the scroll position and the live grep
  to fetch bytes the app already had.
- **The shape that made it cheap is the parallel buffer.** The view keeps `stamps[]`
  beside `lines[]` rather than prefixing the stamp into the line, and `internal/tui/logs.go`
  splits once at the boundary through a new `kube.SplitLogTimestamp` (a thin export over
  the resumer's existing `parseLogTimestamp`, so the two parsers cannot drift). Two things
  follow that would not otherwise be expressible. With the toggle off, `shown()` takes the
  same `strings.Join(m.lines, "\n")` it always took — the unfiltered high-throughput path
  pays *nothing* for a feature that is off, which matters while the throughput dogfood is
  still open. And the grep matches the message in both display states, so a query can never
  be satisfied by the clock — the alternative (prefixing) would have made the same query
  narrow differently depending on whether timestamps happened to be on screen. That is
  D148's load-bearing half and it has a test in both states.
- Three smaller calls. (1) **No header marker.** D146 says name display state the reader
  can lose sight of; sharpened, that means `[wrap]` is needed (wrapping and clipping look
  identical until a line is too long) and `[ts]` is not (a stamp is on every row the
  instant it is on). The header is clipped from the right at narrow widths, so a segment
  saved is real. (2) **Verbatim, not reformatted.** The stamp is shown exactly as the
  server sent it (`kubectl --timestamps` parity); a shortened format would be a lossy
  choice this leg has no evidence for. (3) **Not hinted.** With six entries already eliding
  at 220 columns, the closed-grep hint line is the scarcest in the app, and this is a
  per-session display toggle that announces itself by putting a stamp on every row. `?` and
  the generated doc carry it. The registry description stays short for the D147 pt 3 reason.
- **The test suite found the width cost for me.** Three new component tests failed on
  first run: an RFC3339Nano stamp is 30 columns, so a stamped line does not fit the
  40-column fixture view the whole file uses, and the assertions were reading a clipped
  line. That is not a bug — it is the feature's actual cost, and the reason it is off by
  default and the reason LOGS-04a's wrap/hscroll are the right companions. The tests that
  are about *what* is drawn got a 100-column `newStampedLogs()`; the clipping itself stays
  covered where it belongs, in the LOGS-04a tests.
- One test unrelated to logs had to move: `TestMergeOverride` overrode `app.filter` to
  `"t"` as "a free, non-nav key". `t` is not free any more, and the collision check caught
  it — the merge test now uses `v`. Worth knowing that the default map's free-letter
  supply is what those tests are quietly spending.
- Decisions: D148 — fetch a stream's cheap optional metadata always and toggle its
  *display*, never restream; store it beside the payload, never prefixed into it; a filter
  matches the payload, not the metadata; a self-announcing toggle does not get a hint slot
  or a header marker.
