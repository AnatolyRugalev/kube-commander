## Why the previous leg's stated fix was the wrong one

D186 pt 2 left a constraint for this leg: *"the pass must read through a client that
implements `GroupsAndMaybeResources` (client-go's memory cache does; the disk cache does
not), and any such change trades against D8's promise that a warm start reconciles the menu
with no network round-trip."* That framing had the leg pre-committed to a trade — pay a
network round trip on every discovery pass, or keep the bug.

The trade is avoidable, and the reason is in the same paragraph that described the defect.
Aggregated discovery marks a failing group/version "stale"; client-go's split drops the
stale version from the group and hands the cause to an `AggregatedDiscoveryInterface` only.
So the *cause* is gone by the time `discoverResources` runs — D186 was right about that —
but the group is not gone. It survives as an entry with an empty `Versions` slice, which is
exactly why `ServerPreferredResources` finds nothing to fetch under it and returns no error:

```go
for _, apiGroup := range serverGroupList.Groups {
    for _, version := range apiGroup.Versions {   // ← zero iterations for a stale group
```

The emptiness *is* the evidence. And it is already on disk: the disk cache persists the
split group list, so reading it costs no round trip and D8 holds. What is lost is the
version number and the wording of client-go's `StaleGroupVersionError` — neither of which
any consumer used. The menu parsed the `GroupVersion` string and immediately threw the
version away; DIAG-01 logs the string as-is.

That is D187, and it makes the shape of the fix small: one extra call to `ServerGroups()`,
already-cached, in the pass that just ran it.

## The type change is the load-bearing part

`FailedGroup` was `{GroupVersion string, Err error}`. A group-granular failure has no
version to put in it, and the naive move — storing the bare group name — is a live bug:
`schema.ParseGroupVersion("metrics.k8s.io")` has no `/` to split on, so it returns
`{Group: "", Version: "metrics.k8s.io"}` and the menu would mark the **core** group
unavailable. Every Pod, Service and ConfigMap row greyed out because metrics-server is
down: the exact 2020 failure mode (#87) this whole line of work exists to prevent,
reintroduced by the fix for it.

So the struct became `{Group, Version, Err}` with `Version` optional, plus a
`GroupVersion()` method for display, and both consumers now use the field they actually
wanted. D187 pt 2 pins that a future leg must not fold it back into one string.

## What the two discovery shapes do, and why they don't collide

| server | broken group in `ServerGroups()` | `ServerPreferredResources()` | reported by |
| --- | --- | --- | --- |
| aggregated (≥1.30 default) | present, `Versions: []` | lists, `err=nil` | `versionlessGroups` (group only) |
| legacy | present, versions intact | `*ErrGroupDiscoveryFailed` | the existing branch (group + version) |

The two are mutually exclusive by construction — a legacy server's broken group keeps its
versions, so `versionlessGroups` cannot see it — and a group already named by the error
branch is skipped anyway, so the version-bearing report always wins. A healthy group on
either server always carries at least one version, which is what keeps this from inventing
failures; the envtest baseline asserts exactly that (`len(base.Failed) != 0` → fatal) before
anything is broken, and it is the assertion that would catch it if the premise were wrong.

## Verification, and the negative case

The hermetic tests pin the parsing: the versionless group is named, the two shapes do not
double-report, and a group-list error costs only the extra reporting (the resources are
already in hand — principle 3, and the reason this cannot make discovery *worse*).

But hermetic tests are what let this defect live for eleven days: a fake returns the shape
the test wrote, so it could only ever confirm that `discoverResources` handles the error
client-go was assumed to produce. The load-bearing check is
`TestEnvtestBrokenAPIGroupIsIsolated`, whose tripwire ("DISC-01 appears fixed — replace this
with the positive assertion") is now that positive assertion: the broken group is present in
`Failed`, its cause is `ErrGroupServesNoVersion`, and it is the *only* entry.

I ran it both ways. With the `versionlessGroups` call removed it fails with
`Failed = []` — the defect, reproduced on demand — and green with it. A test that has not
been watched fail is not evidence, and this one had a specific way of passing vacuously
(assert-something-about-a-slice-nobody-fills).
