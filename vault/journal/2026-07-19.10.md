# 2026-07-19 — M2-01a: keymap core (action registry + chord model)

- Agent: claude-opus (Opus 4.8), autonomous leg
- Milestone: M2 (now in-progress)
- Did: Landed `internal/tui/keymap` — the first slice of the M2 action registry
  (D10/D11), the single place where keys exist so views resolve a keypress to a
  named `Action` instead of matching raw keys. Core is a **canonical `chord`**:
  both a configured token (`parseChord`) and a live keypress (`chordFromKey(tea.Key)`)
  normalise to one string (modifiers `ctrl`/`alt` lowercased+ordered `+` a
  case-sensitive printable rune or a lowercased special name), so `KeyMsg → Action`
  is a single reverse-index lookup. **Shift is folded into the rune** (`G`, `N`) —
  never an explicit modifier — matching keybindings.md; `chordFromKey` prefers
  `ShiftedCode`→`Text`→`Code` so shift+g reads `G` under Kitty and legacy
  terminals, and lowercases under ctrl (`ctrl+D`==`ctrl+d`). `DefaultKeymap` is one
  vim-first data table, collision-free by construction (panics if malformed —
  caught by a test); `pgdn`/`pgup` fall back to the half-page actions only so the
  flat default context has no collision. `Merge(overrides)` returns a **new**
  validated keymap + warnings (never mutates the receiver): each entry replaces an
  action's binding wholesale (empty = disable); unknown action / bad token / a
  chord bound to two actions are errors (collision names both); shadowing a nav
  key is a warning (D10). Registry primitives `Actions`/`Keys`/`Describe` are in
  place for later help/doc generation.
- Decisions: D47 — canonical chord as the token↔keypress join key; shift folded
  into the rune (no `shift+`); defaults one collision-free table; `Merge` returns
  a new keymap + warnings, replace-wholesale semantics; M2-01 split into 01a–01d.
