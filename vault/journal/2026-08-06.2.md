## The board was telling the truth and still hiding an item

Three consecutive legs — HINT-05, BOARD-01, BOARD-02a — ended with the same sentence:
"nothing unblocked remains". Each was correct about what it read. `grep '^- \[ \]'` returns
five items; four are blocked on a human task or on measurements a dogfood has to supply, and
the fifth is BOARD-02b, which is explicitly filed as *not* a do-it-next.

What none of them read is that four closed lines end with a sentence naming work the line
deliberately did not do. Seven things, in prose, none of them a `- [ ]`. One of them —
`:action ` not marking which verbs raise a confirm — is a small, unblocked, entirely ordinary
UI item that any of those three legs could have taken instead of a vault leg.

That is the whole failure, and it is the same shape as D102's and D225's: the leg that writes
the deferral is doing something reasonable (it has just decided *not* to build the thing, and
saying why belongs next to the decision), the cost lands on every later Orient, and it is
invisible in the diff that causes it. The difference is that this one does not merely cost
bytes — it costs legs. Three of them.

## Checking the deferrals was the leg, not writing them down

The temptation was to file all seven and call it a harvest. Two would have been wrong.

**AUTH's first**: "the confirm box clips its message at sixty cells, so a long invocation is
truncated *in the question*." Sixty is `modalMaxWidth` — the width of the **box**, not a
truncation. `modal.View` renders the message through `m.styles.App.Width(iw).MaxWidth(iw)`,
and `Width` word-wraps; `git log -L` puts that line in M2-10, so it has been wrapping since
the component landed and the deferral was never true. Confirmed by rendering it: a scratch
test showed `Run: aws sso login --profile production-eu-central-1-administrator-access ?`
laid out across two lines inside the border, hard-wrapped mid-token, nothing missing. Had
this been filed, the leg that picked it up would have gone looking for a bug that is not
there — which is exactly what D79 and the CRD-01 re-scope are about.

**AUTH's second**: "the offer's confirm has no `HelpContext`, which is HINT-02's fifth case."
True when written on 2026-08-05, and closed the same week by HINT-02 (D217), which added
`HelpConfirm` and a test driving the confirm modal into it. The hint context keys off
`modal.Active()`, not the modal's kind, so the reauth confirm was fixed by a leg that had no
reason to open the AUTH paragraph — and no reason to know it was answering it.

Those two are why D226 pt 1 is written as a rule about *staleness* rather than about
deferrals. A Done entry cannot go stale; it records that something happened. A closed line's
paragraph asserts what is true **now**, and the assertion is what a later leg builds on.

The third correction is smaller but the same kind: CRD-PIN's deferral names "the `R` picker",
which stopped existing when PAL-05b retired it into the palette's `:resource ` stage. The
concern survives the rename; the sentence did not.

## Why "no item until asked" is written down as a form

Three of the five surviving deferrals want a human to want them: an in-place pin chord in
`:resource `, showing which kinds are already pinned, and ranking the row verbs by frequency.
The obvious move is to file them as `- [ ]` — the board would look healthier and an agent
would never again report nothing unblocked.

That is the trap the leg skill names outright ("do not invent a low-value leg to look busy"),
and one of the three argues with a decision: D202 pt 4 keeps pin provenance off the display on
purpose. Filing it converts a considered "no" into a queued "yes" that some future leg
implements without ever reading the reasoning. So the form exists to be a *stopping* answer
that is still legible on Orient. Declined is the stronger version and is kept separate: SEARCH's
field selector has a reason recorded against it (per-kind field support varies, a selector the
kind does not support fails its List, and a failed kind is silent by design — D131 pt 3, so it
would quietly drop most of the scope), and a future leg has to answer that, not rediscover it.

## The guard, and the one thing that makes it more than a phrase list

`TestBoardDeferralsNameTheirDestination` joins each blank-line-separated paragraph above
`## Done`, looks for four phrases the board has actually used, and requires the paragraph to
carry a destination. Paragraph, not line: these sentences wrap across four or five lines at the
90-column margin, and the id answering them is routinely on a different line from the phrase
raising them.

The load-bearing detail is that a destination must be **bold**. The first version accepted any
`Dnn`, and it passed all four offending paragraphs on the first run — the CRD-PIN one cites
D202, the PAL one D209, the AUTH one D216, because of course a paragraph about a closed line
cites the decisions that closed it. A citation is not a destination. Requiring `**D227**` or
`**PAL-06**` means the reference has to be the thing the sentence resolves to, and it also
rules out the emphasis that lives in these same paragraphs: `**no**` and `**shows**` are both
real, in the CRD-PIN sentence, which is why an id needs a hyphen and a decision needs digits.

Both mutations were run against the *original* text rather than a synthetic one, which is what
makes them worth anything: pasting AUTH's real pre-leg sentence back in fails at board.md:457.
The phrase list stays short on purpose (D226 pt 2, following D224 pt 1 on the rune cap): the
reply to a deferral it does not recognise is to name the destination like every other one, not
to widen the list until the check passes.
