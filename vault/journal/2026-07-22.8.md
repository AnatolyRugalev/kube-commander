- Did: Addressed the high-priority feedback `2026-07-22-popups-should-overlay` — the
  help overlay and namespace picker **replaced** the browse body (`Model.View()` set
  `body = help.View()` / `nsPicker.View()`), so the menu + table vanished behind the
  modal. Now each modal composites over the base. Added `internal/tui/overlay.go`
  `overlayCenter(base, box, width, height)`: it builds a lipgloss/v2 layer stack —
  base at the origin, the box centered on top (z1) — and flattens it onto a fixed
  `width×height` canvas (`NewLayer`/`NewCompositor`/`NewCanvas`), so the box occludes
  only its own rectangle and every base cell outside it stays visible; an empty box
  or non-positive area returns the base unchanged (degrade). Changed the three modal
  components (`help`, `picker`, `modal`) so their `View()` returns the **bare** box
  (`styles.PaneFocus.Render(body)`) instead of `lipgloss.Place`-padding it to fill
  the screen. `Model.View()` now always renders `browseBody()` (extracted helper:
  menu + table/welcome) first and, when the help or namespace overlay is open,
  overlays its centered box via `overlayCenter` over that base. The confirm modal is
  converted too (it isn't wired into the shell yet, D88) so it already floats when
  M2-14b/M3 wires it. No dimming of the base — the bordered box stands on its own
  (deferred as an optional refinement). → D95.
- Decisions: D95 — modals composite over the base browse (floating popup), never
