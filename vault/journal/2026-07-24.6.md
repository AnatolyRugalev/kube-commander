# 2026-07-24 — M3-14b-3: exec live terminal resize (SIGWINCH → size queue)

- Agent: claude-opus-4-8
- Milestone: M3
- Did: Wired live window-resize tracking into the exec session so the remote PTY follows
  the local terminal mid-session (14b-1 seeded only the size at exec start). `execCommand.Run`
  now, on the real-terminal path, factors the size read into an injected `sizeOf` closure,
  seeds with it, then starts a new **`watchResize(q, sizeOf)`** goroutine that listens for
  `syscall.SIGWINCH` and on each one reads the current size and calls a new
  **`execSizeQueue.push`**. `push` makes the one-slot queue **latest-wins** — it replaces a
  stale unread size (drop + retry) so a burst of resizes collapses to the newest and the
  signal goroutine never blocks on a slow `remotecommand` reader; `seed` keeps its
  keep-existing initial-size semantics, and both drop a degenerate 0×0 read. Teardown is
  race-safe: `Run` defers the watcher's `stop` after `defer q.close()` so LIFO stops the
  watcher first, and `stop` unregisters the signal and blocks until the pump goroutine has
  exited — so no `push` ever races the closed channel. → D127.
- Decisions: D127 — SIGWINCH watcher pushes the current size into a now latest-wins exec
  size queue; watcher is stopped (signal.Stop + wait) before the queue is closed; resize is
  Linux/macOS only.
