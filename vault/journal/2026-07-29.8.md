- **The marker is the leg's one real decision, and it is not cosmetic (D158).**
  `kube.ContextInfo` already carries a `Current` flag, and using it is the obvious
  move — it is also wrong after the first switch. kubecom's switch is session-scoped
  and deliberately never rewrites the kubeconfig's `current-context` (a TUI that
  mutates the file every other tool reads would change what the user's next `kubectl`
  does), so `Current` answers "what the kubeconfig says", i.e. the context the reader
  *launched from*. The shell's own `m.context` is the truth, so the picker derives the
  marker from it and the launcher's `contextLister` passes no `Context` override at
  all. The failure this avoids is invisible at launch — the two agree until you switch
  — and shows up precisely when someone opens the picker to check where they are.
  `TestContextPickerMarksTheShellsContextNotTheKubeconfigs` flags `dev` as the
  kubeconfig's current while running a shell on `prod` and requires the marker to
  follow the shell; with the mutation `c.Name == current` → `c.Current` it fails on
  both rows.
- **`C`, not `ctrl+<letter>`.** The obvious pick was to join `ctrl+n`/`ctrl+s`/`ctrl+a`/
  `ctrl+w`, since ns.switch is this action's sibling. But that family exists for a
  reason that does not apply here: those gestures act on surfaces with an *always-open*
  query field that swallows every text-carrying key (D140 pt 1). The context picker's
  filter is opt-in (`/`), like the namespace picker's, so a plain key is safe — and the
  free `ctrl+` keys are worth more to the surfaces that genuinely need them. `C` is the
  mnemonic, is free in the flat browse context, is not a reserved nav chord (D10), and
  sits with the other capital-letter app-global gestures (`M`/`F`/`X`). Adding a `ctx.*`
  namespace grew the `?` overlay from 14 columns to 15; bubbles' help elides on width,
  and the hint line was deliberately left alone (it is already the app's scarcest
  surface, D147 pt 3) — the key is discoverable through `?` and the generated doc.
- **What the picker had to *not* be seeded from.** Every other picker in the shell reads
  the cluster; this one reads the kubeconfig. That places the seam (on the Model beside
  the connector, not in the `Cluster` bundle — D155 pt 2's test answers "no" even more
  clearly than it did for the connector) and it removes a guard: the listing carries no
  generation, because a kubeconfig list cannot go stale the way a cluster's data can.
  The one guard left is that a result landing after the picker was dismissed must not
  re-seed or reopen it (`TestLateContextListIsDropped`). It also means the switcher
  keeps working when the current cluster is unreachable — which is exactly when someone
  wants to switch away from it.
- **Degrading, twice.** An unreadable kubeconfig closes the picker with an error toast;
  a kubeconfig declaring no contexts closes it with a neutral notice. The alternative —
  an empty modal you can only escape from — is the shape principle 3 exists to avoid,
  and it is the one thing about this surface a reader could not otherwise interpret.
