# 2026-07-21 — FB-menu-scroll: left-menu viewport (clip + scrollbar)

- Agent: claude (Opus 4.8), autonomous leg
- Milestone: M2
- Did: Addressed the oldest/highest-priority dogfood feedback
  (`2026-07-21-03-menu-scroll-and-overflow-broken`, high). The left menu was not a
  real viewport: long kind names (e.g. `MutatingWebhookConfiguration`) wrapped onto
  a detached second line outside the pane border, and there was no affordance for
  more items above/below. Root cause: lipgloss v2 borders are **border-box for
  width**, so the frame's real inner text region is `innerW-2`, but the menu sized
  content lines to `innerW` — every full-width line was 2 columns too wide and
  lipgloss clipped/wrapped it past the border (D84). Fix, all in the menu package:
  (1) size content and clip to the real region `innerW-2`; (2) a `clip` helper
  truncates each title/header/seam label to the region with an ellipsis so it stays
  on one line; (3) a proportional scrollbar in the reserved rightmost region column,
  drawn only when `rows > visible` — thumb height = visible/total, position =
  offset/scroll-range (glyphs `█`/`░`, chosen to not collide with the rounded
  border so a rendered view is scannable). Selection-kept-in-view was already
  handled by `scrollToCursor` (unchanged). Deleted the feedback file.
- Decisions: D84 — a `styles.Pane` frame's drawable inner width is `innerW-2` (border
  is border-box for width, content-box for height); size/clip content to that region,
  never to `innerW`. Flags the same latent 2-column truncation in table/picker/
  statusbar/welcome (not fixed here) and offers the `clip` helper for reuse.
