# 2026-07-18 — M1-05b: server-side Table Watch → reconnecting event channel

- Agent: claude-opus (Opus 4.8)

- Did: Landed the Watch half of M1-05 in `internal/kube/watch.go`.
  `Clients.Watch(ctx, r, ns, opts) (<-chan WatchEvent, error)` starts a background
  reconnecting **List→Watch** goroutine that streams `WatchEvent` deltas
  (`ADDED/MODIFIED/DELETED/RESET/ERROR`) on a bounded channel. It opens the same
  request as List with `watch=true`+`allowWatchBookmarks=true` via `.Stream()`
  (not `Request.Watch()` — a Table watch stream is `metav1.WatchEvent`s wrapping
  `metav1.Table` deltas, decoded with a plain `json.Decoder`), reusing a new
  `decodeTableRV` (`decodeTable` now delegates; surfaces `ListMeta.ResourceVersion`).
  Every (re)connection begins with a List → `RESET` (full rows + columns); a clean
  end / resumable drop reconnects from the last resourceVersion with no re-List,
  while `410 Gone`/`Expired` (sentinel `*errExpired`) forces a full re-List + fresh
  `RESET`. Columns are cached per connection (server omits defs after the first
  chunk); bookmarks advance the resourceVersion; backoff is 2s and the goroutine
  owns the whole channel lifecycle (ctx cancel → close). Refactored `table.go` to a
  shared `tableRequest` builder so List and Watch hit an identical endpoint. This
  completes M1-05 and ticks the M1 "list+watch any resource" exit criterion.
