# 2026-07-21 — FB-esc-back-to-menu: esc pops table focus back to the left menu

- Agent: claude (Opus 4.8), autonomous leg
- Milestone: M2
- Did: Addressed the oldest dogfood feedback
  (`2026-07-21-04-esc-returns-to-left-pane`, normal). Esc had no "back to the menu"
  gesture: with the right pane (table) focused there was no one-key way to return
  focus to the left menu. Made `nav.back` (esc) the one-level-back key, resolved
  top-down, one level per press — in `handleAction`'s `ActionBack` case: close the
  help overlay if open; else clear a committed table filter (unchanged, now an early
  return); else, with the table focused, pop focus back to the menu (`table.Blur()`
  + `menu.Focus()`); inert when the menu already holds focus. So on a committed
  filter with the table focused, the first esc clears the filter (focus stays), the
  next esc returns focus to the menu — matching the feedback's "clear the filter
  first, then pop focus" one-level-per-press ask. The live-editing esc that cancels
  an in-progress filter is untouched (still handled in `routeFilterKey` /
  `handleFilterAction` while `m.filtering`).
