- Did: Split **SEARCH-02** (search mini-app shell) component-first in the D52 rhythm the
  logs line used (LOGS-01 component → LOGS-02 wire), and built the component half:
  `internal/tui/components/searchview` — a **full-screen** search view with an
  always-open query field over a streaming, cross-kind result list. Shape is borrowed
  from the two established components: full-screen like the logs view (results span
  kinds and want every row, D134) and `list`+delegate like the picker (M2-08a), with the
  list's chrome, native filter, and key bindings disabled so navigation only ever
  arrives as keymap actions (D11). Rows are `kube.SearchHit`s rendered column-aligned —
  the kind padded to the widest kind currently shown, then `ns/name` (a bare name for a
  cluster-scoped hit, whose `Ref.Namespace` is empty) — built by a pure `hitItems` so
  the exact row text is assertable without a rendered View. The view imports
  `internal/kube` for `SearchHit` (as `menu`/`table` already do) rather than defining a
  parallel row type, so the wiring hands hits straight through and drills in from
  `SelectedMsg.Hit` with no index bookkeeping. Three messages, owned here (D56):
  `SelectedMsg` (nav.drillIn on a hit), `ClosedMsg` (nav.back on an empty query), and
  `QueryChangedMsg` (every actual text change). → D140.
- The two choices worth naming: the query field is **always open** (the query is the
  view, not a mode inside it — so there is no `app.filter` toggle here and the root must
  route text keys to `UpdateQuery` the whole time the view is up), and a query change
  **drops the previous query's hits inside the view** before the wiring sees the
  message, so what is on screen always describes what is typed. `nav.back` therefore
  clears query+results first (emitting `QueryChangedMsg{""}` so the wiring can cancel
  the in-flight fan-out) and only closes on a second press — the picker's
  clear-then-cancel gesture (M2-08b). `AppendHit` preserves the cursor row, so hits
  landing during a fan-out can't change what `enter` drills into, and the empty list
  always states which of the three empty states it is (`type to search this cluster` /
  `searching…` / `no matches`) so a slow search never reads as a hung one.
- Decisions: D140 — query field always open (root routes text keys while active); the
  view holds no client and only emits `QueryChangedMsg` (wiring owns launch/debounce/
  cap/cancel); a query change drops stale hits in-view; streaming hits never move the
  cursor; an empty list always says why.
