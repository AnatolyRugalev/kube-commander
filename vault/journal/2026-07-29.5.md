# 2026-07-29 — M4-02: one indirection for the 21 cluster-bound seams

- Agent: claude-opus-5
- Milestone: M4
- Did: Pure refactor, no behavior change. The 21 `With*` seams `run.go` closed over one
  `*kube.Clients` now live in a single `tui.Cluster` value the `Model` embeds, built by
  one constructor (`tui.NewCluster` ← the launcher's `clusterFor`). A context switch
  (M4-04) can now repoint one value instead of 21 closures — the enabler D155 pt 2 asked
  for. Nothing switches yet.

- **Embedding is why the diff is a move, not a rename.** `Cluster`'s fields are
  unexported and promoted, so all ~75 call sites keep reading `m.watcher`, `m.deleter`,
  `m.searcher` … unchanged and the 21 individual `With*` options keep compiling untouched
  (`m.portLister = l` now writes `m.Cluster.portLister`). That matters beyond diff size:
  every existing hermetic test wires exactly one fake seam through its `With*` option,
  and the refactor had to leave that idiom intact or it would have rewritten a third of
  `tui_test.go` — which is precisely the "same seams, same tests" the board item asked
  for. The bulk of the app.go diff is the *comments*: each seam's doc block also
  documented the async state sitting beside it (`watchCh`/`watchCancel`, `logCh`,
  `drainGen`, `pfPorts`), so the blocks were split — seam docs to `cluster.go`, state
  docs left in place. That split is itself useful: the Model's struct now reads as
  per-cluster **state** (what M4-03 must tear down) with the clients factored out.
- **`Cluster` is a value, not a pointer — deliberately, against the board's wording.**
  The board note said "held behind one pointer". A pointer would mean every copy
  bubbletea makes of the `Model` on each `Update` shares one seam struct, so a write
  through any copy is seen by all of them — shared mutable state, which principle 1
  exists to forbid, and the exact bug class the framework choice was made to eliminate. A
  value copies with its `Model`, a swap rebinds only the copy the update loop returns,
  and D155 pt 2's actual requirement ("a switch swaps one value") is met either way.
  `TestClusterSwapRepointsEverySeamAtOnce` pins it: swapping a copy's cluster must not
  disturb the original. No new `Dn` — D155 pt 2 already binds the constraint and
  principle 1 already forbids the pointer, so a decision here would only restate them
  (D67).
- **The reflection test is the point of the leg, not decoration.**
  `TestNewClusterWiresEverySeam` walks `Cluster`'s fields and fails on any nil one after
  `NewCluster`. The failure it guards is the quiet one D155 pt 2 describes: a future leg
  adds a seam, wires it in its own test through `With*`, and forgets the constructor —
  everything compiles, every test passes, and exactly one feature is dead in the shipped
  binary (or, after M4-04, pointed at the previous cluster). Reflection rather than 21
  assertions specifically so a *new* field is covered without anyone remembering to
  extend the test. It skips non-interface fields so a future non-seam field can't make it
  panic.
- **`ClusterClient` carries 20 of the 21.** `*kube.Clients` satisfies the union
  interface directly, so `clusterFor` names the client once instead of 21 times and a
  seam added to `ClusterClient` is a compile error at the launcher until the client
  actually implements it. `PortForwarder` is passed as a second argument and cannot join
  the union: `Clients.PortForward` returns the concrete `*kube.PortForward`, not the
  `ActiveForward` the shell observes — the reason `PortForwarderFunc` exists. Keeping the
  adapter in the launcher (rather than teaching `tui` the concrete type) preserves the
  package's client-free boundary.
- Scope note: the context *name* and `--kubeconfig` path stayed on the `Model`. Both are
  per-context, but neither is a client, and `WithContext`/`WithKubeconfig` are the
  launcher's strings; M4-04 sets the name when it swaps and M4-05 owns the rest of the
  per-context state (menu file, last namespace, persister). Folding them in here would
  have widened a no-behavior-change refactor into the switcher's job.
