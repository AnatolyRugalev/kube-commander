# 2026-08-15 — STORY-06b: the S-mode sort — `s` freed, `S` focuses the column-header row, `h`/`l` move, `enter` toggles, `x` clears

- Agent: opencode (do-rewrite-leg, interactive session)
- Milestone: M5 (UX-validation line, D268)
- Did: Landed the redesign's S interaction as a **column-header sort mode** on the
  table instead of the popup the old `2026-08-15-sort-column-picker.md` proposed.
  `sort.column` rebinds `s`→`S` and its meaning becomes "focus the column-header
  row" (description updated); `s` is freed entirely — the s-family is now `S`
  (enter the mode) and `x` (clear) alone, search already on `ctrl+f` (D269).
  While the mode is up, the table owns the keyboard as a capturing surface
  (forwards-panel shape): `h`/`l`/`left`/`right` move a header cursor across the
  visible columns (revealing it through the existing horizontal-scroll machinery,
  clamping at the edges), `enter` toggles the sort direction on the cursor column
  (`SortBy`'s own toggle, D94), `esc`/`S`/`q` return focus to the rows, and `x`
  clears — and the clear resolves the mode too: with the sort gone, `x` lands back
  on the rows, exactly as `esc` leaves it. The cursor is the mode's only new state:
  sorting still rides the table's `SortBy`/`ClearSort`, so watch deltas keep
  re-sorting and `recordViewState` persists on direction/clear. `sort.clear` also
  keeps working everywhere a table is showing (outside-the-mode key + palette
  verb), so nothing is lost. Added the `HelpSort` hint context (HINT-05-complete:
  declared above the count, named, set, reachable) and its `hintContext` case; the
  header row paints the cursor column with the Selection bar when the mode is up,
  and a RESET/delta that shrinks the columns clamps the cursor.
  `docs/keybindings.md` regenerated (`sort.column` `S`, `sort.clear` `x`); the
  palette's `TestMergeOverride` free-key probe moved off the now-taken `x`; the
  default-resolution test pins `S`→ sort.column, `x`→sort.clear and `s` unbound;
  the sort tests rewritten as `TestSortModeFocusesHeaderAndMovesAcrossColumns`,
  `TestSortModeClearProvesTheClearPick` and `TestClearSortKeyRestoresOrder` — the
  clear test asserting the mode resolves with the sort (a follow-up fold after the
  initial commit: `x` now exits the mode too, per the maintainer's read of the
  clear pick).
- Decisions: **D270** — the sort column-picker is a header-focus mode, not a
  popup; `s` is freed; `sort.clear` rides `x` and works anywhere a table is
  showing (placement inside the mode, not exclusivity); the mode is a capturing
  surface with its own HelpSort context. Supersedes the popup design.
