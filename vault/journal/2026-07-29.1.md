- **What the audit found, per criterion.**
  - *Live-updating rows for any discovered kind* — holds. The drill-in → `kube.Watch` →
    pump → table path is M2-07c/D63 with three direct tests; "any discovered kind" is
    covered from both ends (`menu.Reconcile` appending a CRD, and the `:` palette reaching
    the same set pane-free); and `TestProgramFilterFlow` drives it through a real program.
  - *Menu customization persists* — holds, **but only read against D83/D89**, which moved
    customization to a hand-authored per-context `menus/<context>.yaml` and explicitly
    dropped the in-TUI add/remove/reorder the criterion's original wording implies. Ticking
    it without citing that narrowing would have left the next agent free to "finish" M2 by
    building a menu editor D89 already rejected. That is D154 pt 2 and it is the most
    load-bearing thing in this leg.
  - *Vim keys and fallbacks* — holds structurally: resolution is central, so a fallback
    cannot be present in one list and absent in another. `Binding` joins all of an action's
    keys, so the help overlay shows both by construction, not by a maintained list.
  - *Rebinding / invalid keymap / no raw keys* — holds. `runTUI` resolves the keymap
    before the alt-screen, so a bad keymap errors out instead of half-launching. Every raw
    key token in the tree lives under `internal/tui/keymap`; the only `tea.KeyPressMsg`
    consumers left are the text-entry surfaces, where the key *is* the text.
  - *No mutex-guarded UI state* — holds. Zero `sync.Mutex`/`RWMutex`/`Map` under
    `internal/tui`; the single `sync.` is a `sync.Once` closing a channel in `exec.go`'s
    size queue, which lives outside the `tea.Model`.
- **The one real gap, and why it is not a criterion.** The menu handles up/down/top/bottom
  but not half-page/page, so `ctrl+d`/`pgdn` do nothing in the left pane. It was tempting
  to leave the parity criterion unticked over it — but the criterion asks whether vim keys
  *and their fallbacks* both work, and both are equally inert there, so parity is intact
  and the missing actions are an enhancement. Filed as **M2-15** rather than held against
  the milestone (D154 pt 3). The menu does scroll (offset + scrollbar) and discovery
  reconcile grows it, so it is worth doing — just not worth holding M2 open for.
