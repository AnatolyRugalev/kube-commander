## Why the palette and not a chord

The board offered two answers and asked for one: a `ctrl+…` chord inside the resource
picker, or a palette verb. The chord is the smaller diff and the worse gesture, for a
reason that only shows up once you write the sentence a user would read: *"open `R`, find
the kind, press `ctrl+something` instead of Enter."* It needs the picker to be open, which
means it needs you to have decided to pin **before** you started typing — and the whole
premise of the line is that you find a kind while looking for something else. It also
spends a chord on a surface where every letter is already query text, on a keymap where
`ctrl+p`, `ctrl+n`, `ctrl+s`, `ctrl+a` and `ctrl+w` are taken.

The palette verb costs two lines of wiring instead, because PAL-03a built the argument
stage as a general thing: a verb, a space, a list you narrow by typing. `:pin externals…`
is one line of typing that both finds and acts, and it works with no cluster pane focused,
with the menu toggled off, and from inside any browse state — none of which the chord
does. The one thing the chord would have offered and this does not is pinning *the row you
are currently highlighting in `R`* without retyping its name; that is a real convenience
and it is also the case `*` already covers once you have drilled in.

## The refusal had to move, not be copied

The interesting part of this leg is three lines long. `pinResource` used to be one
function: resolve the kind from the cursor, then decide between pin / unpin / decline. The
palette resolves the kind a completely different way, so the temptation is an arm in
`applyPaletteArg` that calls the persister directly — five lines, obviously correct, and
wrong the first time either path grows a case.

It is worse than the usual drift argument because of *what* the divergent branch would get
wrong. The decline case reads a user's hand-written `menus/<context>.yaml` and refuses to
record a pin that file outranks (D193 pt 3). A `:pin ` that skipped that check would write
a line into the state file that can never render, and tell the reader it had pinned
something. The failure is silent, it is about the user's own files, and it would surface
weeks later as "I pinned this and it did nothing". So the split is target-resolution above,
`togglePin` below, and the palette enters at `togglePin` — which is D204 pt 2 and why it is
a decision rather than a note.

## Two ways `:pin ` deliberately differs from `:resource `

- **It needs no watcher.** `:resource ` is inert without one because switching the table is
  what it does; pinning is a note about which kinds you care about and has nothing to do
  with browsing. A shell that cannot watch can still be told what to keep. It *is* inert
  without a pin persister, which is the same rule (`*` is inert there too) applied to the
  seam that actually matters for this verb.
- **It lists only *available* kinds.** `resourcePickerItems` filters to available rows, so
  a kind whose API group failed discovery (D57/D187) is absent from the palette's list —
  while `*` on its unavailable menu row still pins it, deliberately (a group that is down
  right now is precisely one you may want kept). That asymmetry is left as it is: fixing it
  means a second snapshot, and D203 pt 4's whole point is that there is one. The `*` path
  covers the case, and the day something narrows the menu, both surfaces get re-sourced
  together — which is the note now carried on the board.

## One thing worth knowing for the next leg

The palette's verb list is now fourteen entries and every one of them is app-global by the
comment's own rule. `menu.pin` is the first that *reads the cursor when pressed as a key*,
and it fits only because its palette form takes an argument. PAL-04 is about to add verbs
that genuinely act on the selected row with no argument at all — `:logs`, `:delete` — and
the palette has never had to say *which object* it would act on. That is the question to
answer first in PAL-04, before the verb list grows: a `:delete` that lists in a palette
opened over an unclear selection is the one entry in this surface that can do damage.
