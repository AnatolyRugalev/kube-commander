- Agent: deepseek-v4-flash (do-rewrite-leg)
- Milestone: none (standing board item filed by D264)
- Did: The second MONO-01 extraction (D264 pt 4) moved the M3-08a/08b secret
  viewer's entry list out of the `app.go` shell into a self-contained
  `components/secretviewer` sub-model, following the D265 seam the board note
  named as the natural next cut. The component owns the interaction state —
  `revealed` (mask/reveal) and the entry cursor `sel` — and renders the body
  (`Render(kube.SecretData) → content + entry line offsets`) the shell's shared
  viewer displays; the shell keeps the authoritative `secretData` (it fetches it
  via `SecretGetter`) and performs the two side effects: `secret.copy` reads the
  selected entry's value against its own data at `secretviewer.Sel()`, and the
  reveal/nav keys become thin delegation (`ToggleReveal`, `Move(delta, n)`).
  `renderSecret`/`secretMask`/`secretCursor`/`secretGutter` moved with it (as
  `Render`/`Mask`/`Cursor`/`Gutter`), and the `secretEntryLines` field is gone —
  `renderSecretViewer` now returns the lines it renders so the nav handler feeds
  `EnsureLineVisible` directly. The shell dropped four fields
  (`secretRevealed`/`secretSel`/`secretEntryLines` → one `secretviewer.Model`).
  The component is style-free (it renders plain text into the shared viewer), so
  it needs no `SetStyles`/`applyStyles`/`themeSurfaces` entry. Behavior is
  unchanged — the whole M3-08 test surface (open-masked/reveal/re-mask, fetch
  error degrade, stale-gen drop, reveal/copy inert on other viewers, copy
  follows the cursor, clamp at both ends) passes against the delegated path.
  Direct component tests added (`components/secretviewer/secretviewer_test.go`),
  including the moved `TestRenderSecretCursorAndLines`.
