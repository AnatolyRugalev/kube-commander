# 2026-07-19 — M1-08: background port-forward

- Agent: claude-opus (Opus 4.8), autonomous leg
- Milestone: M1
- Did: Landed `Clients.PortForward(ctx, ref, ports)` + the `PortForward` handle in
  a new `internal/kube/portforward.go` — the in-process `kubectl port-forward`
  (D2). It forwards local ports to a pod in a background goroutine over an **SPDY
  dialer** to the pod's `portforward` subresource: `spdy.RoundTripperFor(c.Config)`
  (the transport the `Clients` doc had reserved for exactly this) +
  `spdy.NewDialer(..., "POST", RESTClient().Post().Resource("pods")…
  SubResource("portforward").URL())`, the same upgrade kubectl does — the typed
  clientset REST client, not the dynamic path (port-forward is pod-only; drain/logs
  precedent). `portforward.PortForwarder` does the forwarding (`go ForwardPorts()`);
  kubecom wraps it in a **channel-based handle** — `Ready()` (listeners up),
  `Done()` (forwarding ended), `Err()` (fatal error / nil on clean stop), `Ports()`
  (bound local:remote pairs, for OS-assigned `:<remote>` local ports), `Stop()`
  (idempotent via `sync.Once`). The result is handed off through a **channel
  close, not a mutex** (goroutine writes `err` before closing `doneCh`; `Err` reads
  it only after `doneCh` is closed → happens-before, race-free — principle 1). ctx
  cancellation stops the forward via a bridge goroutine, mirroring Logs/Watch. Own
  `ForwardedPort{Local,Remote uint16}` keeps the TUI boundary client-go-tooling-free
  (D33). Empty pod name / empty port list / malformed port spec rejected before any
  dial (#86).
- Decisions: D45 — SPDY dialer from the retained `*rest.Config`; channel-based
  handle, no mutex-guarded result; ctx-cancel stops à la Logs/Watch; own
  `ForwardedPort` type; injected `forwarderFactory` for hermetic lifecycle tests.
