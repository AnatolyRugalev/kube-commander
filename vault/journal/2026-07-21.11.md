# 2026-07-21 — FB-help-popup: help/keys view is a centered modal, not a full-screen page

- Agent: claude (Opus 4.8), autonomous leg
- Milestone: M2
- Did: Addressed dogfood feedback `2026-07-21-07-help-as-popup` (normal, oldest in the
  inbox after the higher-priority items drained). The `?` help/keys view replaced the
  **whole** TUI body with a raw, top-left, unframed help dump. It is now a **centered,
  bordered modal box** over the browse layout — the same overlay approach the modal
  picker (M2-08a) already uses — so the status bar stays laid out below it and the
  view reads as a popup you dismiss to return to what you were looking at, not a page
  you navigate away to. The `help` component now:
  (1) takes `styles.Styles` (`help.New(s, km)`) and frames its registry-generated full
  help in `styles.PaneFocus` under a `Keybindings` title, then centers the box with
  `lipgloss.Place` over the body area;
  (2) tracks size — `SetWidth` (already wired from `WindowSizeMsg`, drives short-help
  eliding) plus a new `SetHeight`, fed from the app's `resize` alongside the picker's
  `SetSize` with the **body** height (`bodyH`, above the status bar) so the bar is
  never covered and the composed view stays exactly one screen tall;
  (3) renders empty until sized (`width>0 && height>0`), so an unsized program never
  paints a zero-area box;
  (4) constrains the full-help column layout to the modal's inner width using a local
  copy of the embedded bubbles/help model (value receiver), leaving the status bar's
  short-help width untouched.
  Dismissal now covers **esc / `?` / `q`** as the feedback asked: esc (ActionBack) and
  `?` (ActionHelp) already closed it; `q` (ActionQuit) now dismisses the open modal
  instead of quitting the app — a modal owns the quit key until it closes.
- Decisions: none (no new binding constraint — reusing the established picker overlay
  approach for the second modal is applying an existing pattern, not a new one;
  recorded here per D67). Deleted the feedback file.
