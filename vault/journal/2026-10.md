- **KEYS-01** the context keymap engine — `internal/keybind` ports plexos's keymap (KDL `bind`/`unbind`/`group`/`context "<cel>"`/`leader`/`base`, its precedence) over kubecom's focus path, with `focus` (the innermost node) and the field rule; `internal/tui/keymap/default.kdl` holds today's bindings, and a test proves that on 17 surfaces every key resolves as the old map, side tables and field routes did. - **KDL-01** config in KDL — `internal/config` reads `config.kdl` (never written) and `config.overlay.kdl` (the theme picker writes it) in plexos's grammar, `menu ["<context>"] { resource … }` replaces `menus/<context>.yaml`, and state is `state/<context>.kdl`; `--config-dir` replaces `--config`; a start-up notice names a `config.yaml`/`menus/` this kubecom no longer reads; the 2020 migration writes its theme to the overlay. No YAML converter (the maintainer is the only user). _(Decisions: D302)_
- **KEYS-02** the keymap cutover — every key resolves in the context path the Model builds (`keyPath`: cluster, menu or table with its kind, sort, the view, the overlay, a field) through `internal/keybind`; the flat map, `Merge`, `ConfirmAction` and `TableAction` are gone (`context "confirm"` and `focus == 'table'` in default.kdl carry them), and the routers' "mapped and types no text" checks are the field rule now. The user's keymap is config.kdl's then the overlay's, refused at launch at file:line. The hint picks its set from the path (`HelpContextOf`) and shows only keys that act there (an open picker field hints `down`, not `j/down`); the `?` overlay lists the surface under it; sequences display as written (`g g`). `kubecom keys` lists bindings with context and file:line, `keys default` prints default.kdl, `keys check` validates. The nav-shadow warning is retired. _(Decisions: D303)_
- **KEYS-03** a bind's value runs its verb — `bind "g p" "resources.switch" "pods"` switches straight to pods, `ns.switch ""` to all namespaces, `actions.menu "describe"` runs that row action, with no palette. The value runs where the key without one would open the verb's stage (`handleBound` hands it to `openPaletteArg` for that one call), so every surface's routing still decides; a value that names nothing says so on the status line, and a theme name is checked at load. _(Decisions: D303 pt 2)_
- **KEYS-04** the defaults tidied — every default key that does nothing off its surface is bound in that surface's context: the logs view's toggles (`f w t o ctrl+p ctrl+r v V y`), the Secret viewer's `r`/`c`, the forwards panel's `X`, the port picker's `p`/`0`, the search's `ctrl+a`/`ctrl+w`. Each acts where it did; off its surface the letter is free, the `?` overlay stops listing it, and a trace records it as unresolved rather than as an action that did nothing. Keys that also act on the table from the menu stay global. A top-level `unbind` no longer reaches those keys (a deeper context wins, as in plexos), so `kubecom keys check` and a startup notice warn of one. The freed letters' new meanings are a proposal (KEYS-05). _(Decisions: D303 pt 6)_
