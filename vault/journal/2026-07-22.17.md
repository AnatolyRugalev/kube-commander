# 2026-07-22 — FB-crd-parametercodec: CRD list/watch param encoding

- Agent: claude-opus-4.8
- Milestone: M1 (kube layer)
- Did: Addressed high-priority dogfood feedback (`2026-07-22-crd-list-watch-parametercodec`): listing/watching CRDs from non-built-in groups (e.g. `gateway.networking.k8s.io/v1`, `traefik.io/v1alpha1`) blanked the view with "v1.ListOptions is not suitable for converting to …". Root cause: `tableRequest` encoded `VersionedParams` with `scheme.ParameterCodec` (built-in clientset scheme), which can't convert `metav1.ListOptions` to an arbitrary CRD GroupVersion. Switched to `metav1.ParameterCodec` — one line, converts params for any GV (what client-go/dynamic uses), still fine for built-ins. Fixes both List and Watch since both share `tableRequest`. Added a regression test driving `getTable` against a non-built-in GVR (`example.com/v1`) with non-empty ListOptions; verified it fails on the old code and passes on the fix. Added an anti-regression comment in `tableRequest` and deleted the feedback file.
- Decisions: D103 — list/watch params encode with `metav1.ParameterCodec`, never `scheme.ParameterCodec`; hermetic tests must exercise a non-built-in GVR.
