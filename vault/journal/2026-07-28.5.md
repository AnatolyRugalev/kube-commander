# 2026-07-28 — SEARCH-04b: all-namespaces scope widen for cluster search

- Agent: claude-opus-5
- Milestone: M3 (the SEARCH line is a feedback-pulled M4 capability, D131)
- Did: Took the second SEARCH-04 slice. `search.allNamespaces` (`ctrl+w`) searches every
  namespace and re-runs the query already typed; the header swaps the namespace it names
  for `all namespaces` while it is on. The board called this the cheap half and it was —
  the plumbing SEARCH-04a built (`ScopeChangedMsg`, `restartSearch`, per-visit reset,
  debounce) took the second flag as predicted. The interesting part was the two places it
  is *not* symmetric with the kind widen. → D150.
- **A widened scope replaces the name of the default it widens.** D149 pt 3 said "name
  the widened state, not the default", and applied literally that would have appended a
  segment: `search · web · all namespaces · 12 results`. That header claims two namespace
  scopes at once. The rule underneath D149 pt 3 is really *one name per axis* — it looked
  like "only name the exception" only because the kind scope has no default name to
  collide with. The namespace scope is named in every header, so the widen takes that slot
  over rather than adding to it. Consequence worth having: on an app that is already
  unscoped the label is `all namespaces` either way, so the toggle correctly changes
  nothing on screen and nothing on the wire — it is inert, and honestly so.
- **The widen is one-directional: it never touches the app's namespace.** `searchNamespace()`
  reads the view's flag and returns `""`; `m.namespace` is not written, so the browse
  table keeps watching what it was watching and closing the search puts the reader back
  exactly where they were. The tempting alternative — treat "search everywhere" as
  "go everywhere" — would make a search a navigation gesture with a side effect that
  outlives it. A test asserts `m.namespace` after the widen for that reason, not for
  coverage.
- **Two axes, not one cycle.** Kinds and namespaces are independent flags, so all four
  combinations are reachable and each toggle moves only its own. `ScopeChangedMsg` now
  carries *both* flags whichever one moved, so the wiring reads one message instead of
  merging it with remembered state — though in the end nothing in the wiring reads the
  message at all: `searchResources`/`searchNamespace` resolve the scope off the view at
  launch, one source per axis, and `handleSearchScopeChanged` just re-runs. Both widens
  share `restartSearch`, so cancel/supersede/debounce are identical on both axes for free.
- The key is `ctrl+w`, and it is the leg's one grudging choice. It has to be a no-text
  chord (the query field is always open, D140 pt 1); `ctrl+a` — the "all" mnemonic — is
  spent on the kind widen, and `ctrl+n`, the obvious second choice, is `ns.switch` in the
  flat browse context. Binding `ctrl+n` here would have meant a third key *context*
  (the ctxConfirm pattern) plus its routing and doc machinery, which is a leg of its own
  and not this one's. `ctrl+w` reads as cluster-**w**ide — Kubernetes' own phrase for
  "not namespaced" — and costs the query field readline's delete-previous-word, the same
  kind of price `ctrl+a` paid for start-of-line. If a search context ever lands for
  another reason, this binding is the first thing that should move.
- Both widens are hinted in `HelpSearch` (now six entries, still the app's shortest
  context). They are hinted as a *pair* deliberately: the header names a scope but never
  says it can be widened, so a reader staring at `no matches` cannot learn either that the
  kinds were curated or that the search stopped at their namespace — and advertising one
  axis would imply the other is fixed. That is the same rule that kept the logs view's
  self-announcing display toggles out of its full hint line.
- **One regression caught by looking at the binary, not the tests.** `kubecom keys`
  formatted its columns with a hard-coded `%-18s`, and `search.allNamespaces` is the first
  action id to reach 20 characters — so the new row shoved its own description out of
  alignment and nothing in `make check` noticed (no test asserts that output). The columns
  are now sized from the widest value actually printed. Small, but it is exactly the
  "don't regress the running binary" case (D68) that a green gate cannot see, and the next
  long action id would have hit it too.
- Decisions: D150 — scope is independent axes, never a cycle; a widened scope replaces the
  name of the default it widens (one name per axis) rather than adding a second name for
  the same thing; a per-search scope widen never mutates the app's own scope.
