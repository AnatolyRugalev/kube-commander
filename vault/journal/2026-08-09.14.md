# 2026-08-09 — TEST-RUNTIME: the toast auto-clear duration is injectable, so tests stop draining real 5s ticks

- Agent: deepseek-v4-flash (do-rewrite-leg)
- Milestone: none (feedback-driven — `2026-08-09-audit-test-suite-runtime`, Priority: high)
- Did: The audit measured the tui suite at ~190s with ~90s of pure timer-sleep:
  17 tests drained a real 5s (or 10s) toast auto-clear tick because
  `surfaceError`/`surfaceNotice` returned `tea.Tick(errorDisplay)` and the
  `drain` helper executes commands synchronously. Made the duration a `Model`
  field (`toastTimeout`, defaulted to `errorDisplay` at construction) overridable
  with a new `WithToastTimeout(d)` option, the established seam; `sized`/
  `sizedWith` now construct every hermetic test model with
  `WithToastTimeout(time.Nanosecond)` (an explicit option still wins). The
  named 5s/10s tests (`TestPinTwiceUnpinsAndRemovesTheRow`, `TestScale…`,
  `TestPinIsANoOp…`, etc.) drop from 5–10s to 0.01s; the tui package goes from
  ~190s to ~90s. The blocking-tick workarounds in `themeCmdMsgs`,
  `copiedClipboard` and the logs fallback helper now filter the instantly
  arriving `noticeClearMsg`/`errorClearMsg` instead of skipping a blocking tick.
  Feedback file deleted. The remaining suite cost is the *search debounce*
  (250ms, a separate timer) — measured, not in this item's ask.
- Decisions: D262 (toast duration is a per-model option defaulting to 5s; tests
  default to ~0 via the helpers; new helpers that collect a batch's instant
  sub-commands must filter the toast-clear messages; `tea.Tick` must read
  `m.toastTimeout`, never the const).
