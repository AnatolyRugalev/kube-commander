- [x] **M1-07d** Reconnecting/resuming follow logs (`internal/kube/logs.go`) — a **Follow** stream now survives a transient transport drop, extending the M1-07c single-connection core into a reconnecting loop à la watch (D34). `runLogStream` dispatches on `follow`: the non-follow path is unchanged (single connection, verbatim); the follow path (`followLogStream`) reopens on a drop. **Resume mechanics:** logs have no resourceVersion, so Follow **forces `Timestamps` on the wire** (every raw line `"<RFC3339Nano> <content>"`), records the last-seen line's timestamp, and on reconnect sets `SinceTime` to it (`SinceSeconds`/`TailLines` cleared — initial-read only). Timestamps are **stripped before delivery unless `opts.Timestamps`**; an unparseable prefix degrades to verbatim, never dropped. **Dedup:** `SinceTime` is second-granular (metav1.Time → RFC3339 seconds), so resuming re-serves the whole last second; the `logResumer` holds the raw lines already delivered in that second and drops the re-serves, delivering only genuinely-new lines (incl. ones missed *during* the drop), then clears the window on the next second. **Stop vs reconnect:** `bufio.Scanner` reports nil at `io.EOF`, so a clean end (container's log ended, à la `kubectl -f` exiting) stops the follow; any other read error reconnects. **Errors:** first open failure is terminal (one `LogEvent{Err}`, like non-follow); a *reconnect* open/read failure is transient — silent backoff (`logRetryBackoff`, the watch twin, a package var so tests shrink it, D40) + retry bounded by ctx — because a `LogEvent{Err}` is the terminal event by contract.
